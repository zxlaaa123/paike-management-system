# V6_README

## 0. 当前状态校准（2026-06-07）

本目录是早期 V6 规划文档。当前产品功能线实际做到 V1-V5；数据库脚本中的 `v6_*.sql`、`v7_*.sql` 等只是迁移脚本编号，不代表产品版本已经进入 V6。

现状判断：

1. V6 的方向仍然成立：稳定化、工程化治理、回归、审计、性能基线、数据一致性。
2. 文档不能直接照旧开工：V5 已经吸收了部分“修复、试算、一致性检查、回归基础表”能力。
3. 当前代码已经有 `/api/v6/audit-logs`、`/api/v6/audit-logs/{id}` 与 `system_audit_log`；但没有 `regression_test_run`、`performance_baseline_record` 等完整 V6 治理表。
4. 后续继续 V6 时，应先收口“审计日志最小闭环”，再评估回归中心、性能基线和迁移状态展示。

详细校准见：`V6_10_现状校准与执行建议.md`。

## 一、版本定位

V6 版本建议命名为：

> 稳定化与工程化治理版

V6 不再继续横向堆新排课功能，而是承接 V1-V5 已完成能力，重点解决长期维护中的系统稳定性、数据一致性、回归测试、性能基线、数据库迁移、审计追踪和前端状态一致性。

V6 的核心目标是让系统从“功能完整”升级为“可验证、可回归、可部署、可追溯”。

## 二、与 V1-V5 的关系

| 版本 | 定位 | V6 处理方式 |
|---|---|---|
| V1 | 基础数据、手动排课、课表查询 | 保持兼容，纳入回归测试 |
| V2 | 自动排课、规则配置、评分报告 | 保持兼容，纳入性能与回归基线 |
| V3 | 学期、方案、评分明细、应用、回滚 | 作为数据边界治理重点 |
| V4 | 分析诊断、锁定、局部调整、报告 | 作为一致性和审计治理重点 |
| V5 | 智能修复、候选位置、试算方案 | 作为安全边界和解释一致性治理重点 |
| V6 | 稳定化、工程化、自动化验收 | 不推翻前五版，只治理和增强 |

## 四、V6 成功标准

1. V1-V5 主链路可一键回归。
2. 正式课表写入路径可审计、可回滚、可追踪来源。
3. 自动排课、局部重排、智能修复有性能基线。
4. 学期、方案、锁定课程边界有后端一致性检查。
5. 数据库升级不再依赖手工改表。
6. 前端危险操作有明确状态、确认和失败提示。
