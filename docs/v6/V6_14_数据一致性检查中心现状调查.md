# V6_14_数据一致性检查中心现状调查

更新时间：2026-06-08

## 一、结论

V6 第三阶段“数据一致性检查中心”不应从零新增 `data_consistency_check_run` / `data_consistency_issue`。

当前代码已经有 V5 一致性检查基础：

1. 表：`schedule_consistency_check`
2. 实体：`ScheduleConsistencyCheck`
3. Mapper：`ScheduleConsistencyCheckMapper`
4. Service：`V5ConsistencyCheckService`
5. 报告 VO：`V5ConsistencyCheckReportVo`
6. 问题 VO：`V5ConsistencyIssueVo`
7. V5 试算详情页已有一致性检查入口

因此 V6 最小可交付版本复用 `schedule_consistency_check`，补 V6 治理视图、列表、详情、问题清单和触发入口。

## 二、已有能力

`schedule_consistency_check` 字段覆盖 `semester_id`、`plan_id`、`source_plan_id`、`schedule_id`、`check_type`、`check_scope`、`status`、`issue_count`、`blocking_issue_count`、`result_summary`、`detail_json`、`checked_at`、`created_at`、`updated_at`。

`detail_json` 内保存 `V5ConsistencyCheckReportVo`，包含完整 `issues` 问题清单。

`V5ConsistencyCheckService` 已覆盖：

1. 学期血缘一致性。
2. 来源方案血缘一致性。
3. 试算方案状态。
4. 锁定课程保护。
5. 局部重排范围边界。
6. 方案项数据完整性。
7. 教学任务重复。
8. 硬冲突。
9. 教师不可用时间。
10. 教室容量和类型。
11. 禁止正式课表被试算直接覆盖。

## 三、本阶段最小范围

本阶段新增：

1. V6 后端接口：
   - `GET /api/v6/consistency-checks`
   - `GET /api/v6/consistency-checks/{id}`
   - `POST /api/v6/consistency-checks/run`
2. V6 前端页面：
   - `/v6/consistency-checks`
   - 菜单：`V6 系统治理 -> 一致性检查`
   - 列表、筛选、分页、详情弹窗、问题清单
   - 可输入 `taskId` 与 `planId` 触发检查

本阶段不做：

1. 新建 `data_consistency_check_run` 表。
2. 新建 `data_consistency_issue` 表。
3. 自动修复正式课表。
4. 大屏统计。
5. 跨所有正式课表的一键全局扫描。
