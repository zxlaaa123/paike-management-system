# V6_09_AI开发规则与提示词

## 一、总规则

V6 开发中，AI 必须遵守以下规则：

1. 不重写整个项目。
2. 不推翻 V1-V5 业务设计。
3. 不修改正式课表写入边界。
4. 不让 AI 修复直接修改正式课表。
5. 不删除已有表和字段。
6. 不破坏已有接口兼容性。
7. 每个阶段完成后必须回归旧功能。

## 二、开发前必须阅读

开发 V6 前必须阅读：

1. `docs/V1-V5_后续开发建议_2026-05-21.md`
2. `docs/v6/V6_README.md`
3. `docs/v6/V6_01_版本需求说明.md`
4. `docs/v6/V6_02_功能模块设计.md`
5. 当前阶段对应文档

## 三、禁止事项

### 3.1 禁止重写

禁止：

1. 重写自动排课算法。
2. 重写方案应用机制。
3. 重写登录认证机制。
4. 重写前端路由结构。
5. 重写数据库 schema。

### 3.2 禁止绕过边界

禁止：

1. 自动排课直接写正式课表。
2. 局部重排直接写正式课表。
3. 智能修复直接写正式课表。
4. 一致性检查自动修改正式课表。
5. 前端绕过后端校验。

### 3.3 禁止破坏兼容

禁止：

1. 改动 V1-V5 已有接口路径。
2. 改动已有字段含义。
3. 删除已有页面入口。
4. 删除已有测试脚本。
5. 改动已有错误响应格式而不兼容。

## 四、推荐开发顺序

1. 阶段 0：基线检查。
2. 阶段 1：审计日志。
3. 阶段 2：回归测试中心。
4. 阶段 3：数据一致性检查。
5. 阶段 4：性能基线。
6. 阶段 5：数据库迁移和错误码。
7. 阶段 6：总体验收。

## 五、代码实现要求

后端要求：

1. Controller 只做参数接收和响应返回。
2. Service 承担业务逻辑。
3. Mapper 只做数据访问。
4. 正式课表相关写操作必须事务化。
5. 关键失败必须返回稳定错误码。
6. 新增表必须有实体、Mapper、Service、接口和测试。

前端要求：

1. API 文件放入 `frontend/src/api`。
2. 页面放入 `frontend/src/views/v6`。
3. 路由统一注册到 `router/index.ts`。
4. 危险操作必须二次确认。
5. 失败提示必须展示后端错误原因。
6. 空状态、加载状态、失败状态必须处理。

## 六、阶段提示词模板

### 6.1 阶段开始提示词

```text
现在开始 V6 阶段 X。
请先阅读 docs/v6 中对应阶段文档，确认不破坏 V1-V5 已有能力。
本阶段只实现当前阶段目标，不扩展无关功能。
所有新增接口使用 /api/v6 前缀。
完成后运行必要测试，并说明影响范围。
```

### 6.2 阶段验收提示词

```text
请对 V6 阶段 X 做验收。
重点检查：
1. 是否符合 V6 文档；
2. 是否破坏 V1-V5；
3. 是否存在正式课表直接写入风险；
4. 是否有事务、错误码、日志；
5. 前端失败提示是否清晰。
输出发现的问题和修复建议。
```
