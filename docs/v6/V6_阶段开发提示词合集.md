# V6_阶段开发提示词合集

## 阶段 0：开发前基线检查

```text
现在开始 V6 阶段 0：开发前基线检查。

目标：
确认当前 V1-V5 主链路稳定，允许进入 V6 开发。

请检查：
1. 后端是否可启动；
2. 前端是否可启动；
3. 登录是否正常；
4. V1 基础数据和手动排课是否正常；
5. V2 自动排课是否正常；
6. V3 学期和方案机制是否正常；
7. V4 分析、锁定、局部调整是否正常；
8. V5 智能修复、候选位置、试算方案是否正常。

不要修改业务代码。
输出检查结果和 P0 阻塞。
```

## 阶段 1：审计日志能力

```text
现在开始 V6 阶段 1：审计日志能力。

目标：
新增关键写操作审计日志，不改变原业务行为。

请实现：
1. system_audit_log 表；
2. 审计日志实体、Mapper、Service；
3. 审计日志查询接口；
4. 接入应用方案、回滚、手动调整、锁定、解锁、应用试算方案；
5. 成功和失败都记录。

要求：
不破坏 V1-V5 接口。
正式课表写入仍保持原事务边界。
```

## 阶段 2：回归测试中心

```text
现在开始 V6 阶段 2：回归测试中心。

目标：
记录和展示 V1-V5 回归测试结果。

请实现：
1. regression_test_run 表；
2. regression_test_case_result 表；
3. 回归批次创建和查询接口；
4. 用例结果查询接口；
5. 前端回归测试页面。

要求：
先支持记录结果，不要求一开始就自动执行所有测试。
```

## 阶段 3：数据一致性检查中心

```text
现在开始 V6 阶段 3：数据一致性检查中心。

目标：
检查学期、方案、锁定课程、试算方案边界。

请实现：
1. data_consistency_check_run 表；
2. data_consistency_issue 表；
3. 学期一致性检查；
4. 方案一致性检查；
5. 锁定课程一致性检查；
6. 试算方案隔离检查；
7. 前端一致性检查页面。

要求：
一致性检查只报告问题，不自动修改正式课表。
```

## 阶段 4：性能基线中心

```text
现在开始 V6 阶段 4：性能基线中心。

目标：
记录自动排课、冲突检测、局部重排、候选位置生成等关键操作耗时。

请实现：
1. performance_baseline_record 表；
2. 性能记录服务；
3. 性能查询接口；
4. 性能摘要接口；
5. 前端性能基线页面。

要求：
性能统计不能阻塞主业务流程。
```

## 阶段 5：数据库迁移和错误码治理

```text
现在开始 V6 阶段 5：数据库迁移和错误码治理。

目标：
建立数据库版本化升级和统一错误码能力。

请实现：
1. 引入 Flyway 或 Liquibase；
2. 将 V6 新表拆成迁移脚本；
3. api_error_code 表；
4. 错误码查询接口；
5. 前端错误码中心；
6. 关键接口返回稳定错误码。

要求：
不能破坏现有 schema.sql 开发体验，必要时保留兼容说明。
```

## 阶段 6：总体验收

```text
现在开始 V6 阶段 6：总体验收。

目标：
确认 V6 治理能力完整可用。

请执行：
1. V1-V5 主链路回归；
2. V6 回归测试中心验收；
3. V6 一致性检查验收；
4. V6 性能基线验收；
5. V6 审计日志验收；
6. 前端构建；
7. 后端测试；
8. Playwright 关键用例。

输出：
1. 通过项；
2. 失败项；
3. P0/P1/P2 问题；
4. 是否允许合入主线。
```
