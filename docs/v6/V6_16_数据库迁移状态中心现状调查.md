# V6 阶段 5 数据库迁移状态中心现状调查

调查日期：2026-06-08

## 一、现状结论

当前项目没有 Flyway/Liquibase，也没有迁移历史表。数据库初始化主要由 Spring SQL Init 执行 `spring.sql.init.schema-locations` 中显式配置的 SQL 脚本，并辅以少量 Java `CommandLineRunner` 初始化器。

阶段 5 最小可交付版不引入新迁移框架，不改变启动初始化行为，只做只读展示。

## 二、SQL 初始化脚本

当前 `backend/src/main/resources/db` 下共有 29 个 SQL 文件，`application.yml` 中已显式配置执行 29 个脚本。

本阶段接口会对每个脚本展示：

1. 脚本名。
2. classpath 资源路径。
3. 是否出现在 `schema-locations`。
4. 是否存在于 classpath。
5. 配置执行顺序。
6. 粗略风险等级。
7. 幂等/风险说明。

## 三、Java 初始化器

当前识别到的启动初始化器：

1. `AdminUserInitializer`：确保默认管理员账号存在。
2. `SemesterSchemaInitializer`：兜底创建学期相关列和索引。

未发现独立的 Flyway/Liquibase 迁移器，也未发现可直接复用的迁移历史记录表。

## 四、本阶段交付

后端：

1. `GET /api/v6/migrations/status`
2. `DatabaseMigrationStatusService`
3. 只读返回 SQL 脚本配置状态和 Java 初始化器状态。

前端：

1. `/v6/migrations`
2. V6 系统治理菜单新增“数据库迁移”。
3. 展示脚本总数、已配置、缺失、未配置统计。
4. 展示 SQL 脚本表和 Java 初始化器表。

## 五、后续增强

1. 如果未来引入 Flyway/Liquibase，再补迁移历史和执行耗时。
2. 如果继续使用 Spring SQL Init，可增加更严格的 SQL 幂等检测。
3. 可在开发环境增加“脚本未配置但存在”的告警。
