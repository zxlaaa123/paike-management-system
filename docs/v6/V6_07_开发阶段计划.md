# V6_07_开发阶段计划

## 一、开发原则

V6 分阶段推进，每个阶段完成后必须回归 V1-V5 主链路。

原则：

1. 每次只开发一个阶段。
2. 不重写已有排课算法。
3. 不破坏已有接口。
4. 不直接修改正式课表写入边界。
5. 后端校验优先于前端提示。

当前推荐执行顺序（2026-05-26）：

1. 阶段 0 先更新开发前检查记录，确认当前 V1-V5 主链路和本地环境。
2. 阶段 1 只做审计日志最小闭环：建表、服务、接入少量关键写操作、查询接口。
3. 阶段 2/3 不直接照旧草案重复建设，先评估 V5 已有 `schedule_regression_test`、`schedule_consistency_check` 能否复用。
4. 性能基线、迁移状态、错误码治理放在审计日志稳定后推进。

## 二、阶段 0：开发前基线检查

目标：确认当前系统可进入 V6。

任务：

1. 检查后端启动。
2. 检查前端启动。
3. 检查登录和权限。
4. 快跑 V1-V5 主链路。
5. 记录 P0 阻塞。

交付物：

1. `V6_00_开发前检查记录.md` 填写结果。
2. 当前可开发结论。

## 三、阶段 1：审计日志能力

目标：追踪关键写操作。

任务：

1. 新增 `system_audit_log` 表。
2. 后端封装审计日志服务。
3. 接入应用方案、回滚、手动调整、锁定、试算应用操作。
4. 提供审计日志查询接口。

验收：

1. 成功和失败操作都记录。
2. 日志能关联学期、方案、操作人。
3. 不影响原业务事务一致性。

## 四、阶段 2：回归测试中心

目标：沉淀 V1-V5 回归结果。

任务：

1. 新增回归批次表和用例结果表。
2. 提供创建回归批次接口。
3. 接入现有 API smoke 和 Playwright 用例结果。
4. 前端展示回归批次和失败原因。

验收：

1. 可查看最近一次回归结果。
2. 可按 V1-V5 筛选用例。
3. 失败用例有错误信息。

## 五、阶段 3：数据一致性检查中心

目标：检查学期、方案、锁定、试算数据边界。

任务：

1. 新增一致性检查批次表和问题表。
2. 实现学期一致性检查。
3. 实现方案一致性检查。
4. 实现锁定课程一致性检查。
5. 实现试算方案隔离检查。

验收：

1. 能发现跨学期数据异常。
2. 能发现锁定课程被修改。
3. 能发现试算方案污染正式课表。
4. 检查只报告问题，不自动改数据。

## 六、阶段 4：性能基线中心

目标：记录关键排课操作耗时。

任务：

1. 新增性能基线表。
2. 自动排课记录耗时。
3. 冲突检测记录耗时。
4. 局部重排记录耗时。
5. 候选位置生成记录耗时。
6. 前端展示性能趋势。

验收：

1. 每类关键操作有耗时记录。
2. 可查看平均耗时和最大耗时。
3. 性能统计失败不影响主流程。

## 七、阶段 5：数据库迁移和错误码治理

目标：提升部署和错误定位能力。

任务：

1. 引入 Flyway 或 Liquibase。
2. 将 V6 新表纳入迁移脚本。
3. 统一后端错误码。
4. 前端统一展示错误码提示。

验收：

1. 新环境可自动创建 V6 表。
2. 启动时可确认迁移状态。
3. 接口失败返回稳定错误码。
4. 前端不再静默失败。

## 八、阶段 6：V6 总体验收

目标：确认 V6 可合入主线。

任务：

1. 运行 V1-V5 回归。
2. 运行 V6 治理接口测试。
3. 运行前端构建。
4. 运行关键 Playwright 用例。
5. 整理验收报告。

验收：

1. 无 P0 阻塞。
2. P1 问题有明确记录和处理计划。
3. V6 文档、接口、页面、数据库一致。
