# V6_10_现状校准与执行建议

更新时间：2026-06-08

## 一、结论

`docs/v6` 仍有参考价值，但它是早期 V6 草案，不能直接照旧开工。

当前产品功能线实际做到 V1-V5；数据库脚本里的 `v6_*.sql`、`v7_*.sql`、`v8_*.sql` 等是迁移脚本编号，不等于产品版本已经进入 V6。

## 二、当前实现对照

当前代码已经存在 V6 审计日志查询接口、审计日志表与前端只读页面；其余 V6 草案表仍未实现：

| 草案表 | 当前状态 |
|---|---|
| `system_audit_log` | 已实现：`v12_system_audit_log.sql` |
| `regression_test_run` | 未实现 |
| `regression_test_case_result` | 未实现 |
| `data_consistency_check_run` | 未实现 |
| `data_consistency_issue` | 未实现 |
| `performance_baseline_record` | 未实现 |
| `api_error_code` | 未实现 |

当前已有 `/api/v6/audit-logs`、`/api/v6/audit-logs/{id}` 与前端 `/v6/audit-logs`；其他 V6 草案接口仍只能视为目标契约。

当前 V5 已经具备部分相近能力：

| 当前能力 | 已有载体 |
|---|---|
| 修复任务 | `schedule_repair_task` |
| 修复建议 | `schedule_repair_suggestion` |

| 回归基础记录 | `schedule_regression_test` |

## 三、过时点

1. “数据一致性检查中心”不能再从零设计，必须先复用或扩展 V5 一致性检查。
2. “回归测试中心”不能直接新增同语义表，必须先确认 `schedule_regression_test` 是否够用。
3. `/api/v6/audit-logs` 与前端审计日志页已存在；其他 V6 文档接口只能视为目标契约。
4. “数据库迁移中心”需要结合当前 SQL + Java initializer 混合维护现状，不宜贸然引入 Flyway/Liquibase。
5. V6 文档没有吸收 B1/D4/A1 后的评分与本地开发状态，但这些不影响 V6 治理方向。

## 四、仍然成立的方向

1. 不重写自动排课算法。
2. 不推翻 V3 方案机制。
3. 不绕过 V5 试算方案机制。
4. V6 以治理、审计、回归、性能、迁移状态和错误提示为主。
5. 所有新增能力优先只读或旁路记录，不直接改变正式课表写入语义。

## 五、第一阶段当前结果

V6 第一阶段已经按“审计日志最小闭环收口”推进，并完成 P0/P1 范围。

范围：

1. 保留已实现的 `system_audit_log` 表、审计日志服务、审计查询接口。
2. 已补齐关键写操作审计覆盖：
   - 应用方案。
   - 回滚方案。
   - 锁定/解除锁定。
   - 手动排课新增、删除。
   - V4 局部调整应用。
   - V4 局部重排方案创建。
   - V5 试算生成、局部重排试算、应用试算方案。
   - 自动排课运行。
3. 已提供前端审计日志只读页：
   - 路径：`/v6/audit-logs`
   - 筛选：操作类型、学期、方案、成功/失败。
   - 明细：列表分页、详情弹窗。

已验证：

1. `mvn test`：208 个用例通过。
2. `npx vue-tsc -b`：通过。
3. `npx vite build`：通过，仅有 chunk 体积警告。
4. 浏览器联调：`/v6/audit-logs` 列表、详情、筛选、重置均返回 200，控制台无错误。

剩余低优先级观察项：

1. V5 generate/localReplan 失败审计在部分失败路径中 `semesterId` 可能为空，后续可按筛选需求补充。
2. V4 local replan 失败路径会重读来源方案，当前 MySQL 场景无阻塞风险。
3. V5 修复建议生成、标记试算、任务建议状态更新仍属于 P2 候选范围。

验收：

1. 成功操作有审计记录。
2. 失败操作在不破坏原事务语义的前提下尽量记录。
3. 审计记录能关联操作类型、目标类型、目标 ID、学期、方案、操作人和结果。
4. 原有 V1-V5 核心链路不受影响。

## 六、暂缓事项

以下事项不建议作为 V6 第一阶段：

1. 完整回归测试中心。
2. 完整数据一致性检查中心。
3. 性能基线趋势页面。
4. Flyway/Liquibase 迁移体系切换。
5. 全量错误码体系重构。

这些事项适合在审计日志稳定后逐项独立开分支。
