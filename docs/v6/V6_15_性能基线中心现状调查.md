# V6_15_性能基线中心现状调查

更新时间：2026-06-08

## 一、结论

当前代码没有独立性能基线表和 V6 性能查询接口。V6 第四阶段需要新增 `performance_baseline_record`，并把性能统计设计为旁路治理数据。

核心原则：

1. 性能记录失败不能阻塞主业务。
2. 记录关键排课操作耗时和数据规模。
3. 第一版只做列表和摘要，不做复杂趋势图。

## 二、本阶段范围

新增：

1. 表：`performance_baseline_record`
2. 后端：
   - `PerformanceBaselineRecord`
   - `PerformanceBaselineRecordMapper`
   - `PerformanceBaselineService`
   - `PerformanceBaselineController`
3. 接口：
   - `GET /api/v6/performance/baselines`
   - `GET /api/v6/performance/summary`
4. 前端：
   - `/v6/performance-baselines`
   - 菜单：`V6 系统治理 -> 性能基线`
   - 摘要卡片、列表、筛选、分页

接入性能记录：

1. 自动排课。
2. V4 创建局部重排方案。
3. V5 生成试算方案。
4. V5 生成局部重排试算。
5. V5 应用试算方案。

## 三、暂缓内容

1. 复杂趋势图。
2. 性能退化自动判定。
3. 全量冲突检测、评分、风险诊断等所有服务的耗时记录。
4. CI 性能基线对比。

## 四、验收标准

1. 自动排课等关键操作会尝试写入性能记录。
2. 性能记录失败不影响主流程。
3. 性能列表接口返回分页数据。
4. 性能摘要接口返回按操作类型聚合结果。
5. 前端页面可访问、可筛选、可刷新。
6. 后端测试通过。
7. 前端类型检查和构建通过。
8. 浏览器联调通过。
