# V6_13_回归测试中心现状调查

更新时间：2026-06-08

## 一、结论

V6 第二阶段“回归测试中心”不应按旧草案从零新增 `regression_test_run` / `regression_test_case_result`。

当前代码已经有 V5 基础表和后端记录能力：

1. 表：`schedule_regression_test`
2. 实体：`ScheduleRegressionTest`
3. Mapper：`ScheduleRegressionTestMapper`
4. 请求对象：`V5RegressionTestRecordRequest`
5. VO：`V5RegressionTestVo`
6. Service：`V5Stage1DataService.recordRegressionTest`
7. Service：`V5Stage1DataService.listRegressionTests`

因此 V6 最小可交付版本应复用 `schedule_regression_test`，先补只读查询中心。

## 二、已有能力

### 2.1 数据表

来源：`backend/src/main/resources/db/v5_stage1.sql`

1. `semester_id`
2. `plan_id`
3. `source_plan_id`
4. `test_suite`
5. `test_case`
6. `test_stage`
7. `status`
8. `duration_ms`

10. `build_version`
11. `error_message`
12. `extra_json`
13. `executed_at`
14. `created_at`
15. `updated_at`

这些字段足够支撑第一版只读列表、筛选和详情。

### 2.2 后端代码

已有：

1. `ScheduleRegressionTest`
2. `ScheduleRegressionTestMapper`
3. `V5RegressionStatus`
4. `V5Stage1DataService.recordRegressionTest`
5. `V5Stage1DataService.listRegressionTests`

不足：

1. 没有 V6 回归测试中心 Controller。
2. 没有分页接口。
3. 没有按状态、套件、学期、方案筛选。
4. 没有详情接口。

### 2.3 测试脚本和报告

已有脚本：

1. `scripts/api-smoke-test.js`
2. `tests/stage6.spec.ts`
3. `tests/stage7.spec.ts`

这些脚本可作为后续真实回归执行器的数据来源，但本阶段不做自动运行调度。

## 三、旧 V6 文档过时点

旧文档里的 `regression_test_run` / `regression_test_case_result` 属于目标形态，不适合当前直接执行。

原因：

1. 当前已有 `schedule_regression_test`，直接新建同语义表会重复。
2. 当前需求是最小可交付只读中心，不需要先做批次/用例双表模型。
3. 真实一键运行回归测试需要更多环境约束，适合后续独立阶段。

## 四、本阶段最小范围

本阶段只做：

1. V6 后端只读查询接口：
   - `GET /api/v6/regression-tests`
   - `GET /api/v6/regression-tests/{id}`
2. 支持筛选：
   - `testStage`
   - `testSuite`
   - `status`
   - `semesterId`
   - `planId`
3. 前端只读页面：
   - `/v6/regression-tests`
   - 菜单：`V6 系统治理 -> 回归测试`
   - 列表、筛选、分页、详情弹窗

本阶段不做：

1. 新建 `regression_test_run` 表。
2. 新建 `regression_test_case_result` 表。
3. 一键运行全部回归测试。
4. 前端大屏统计。
5. 自动写入测试结果。

## 五、验收标准

1. 后端列表接口返回分页结果。
2. 后端详情接口返回单条记录。
3. 前端页面可访问。
4. 前端筛选和重置可用。
5. 前端详情弹窗可用。
6. 后端测试通过。
7. 前端类型检查通过。
8. 前端构建通过。
9. 浏览器联调通过。
