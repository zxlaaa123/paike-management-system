# V6_00_开发前检查记录

## 一、检查目的

V6 开发前必须确认 V1-V5 基础能力稳定，避免在不稳定基线上继续扩展治理能力。

V6 的开发原则是：

1. 不重写 V1-V5。
2. 不破坏已有接口。
3. 不改变正式课表写入边界。
4. 不让智能修复直接修改正式课表。
5. 先检查、再治理、后增强。

## 五、开发前结论

当前结论：无 P0 阻塞，可进入 V6 阶段 1“审计日志最小闭环”的设计与实现。

已确认：

1. 前后端在线，管理员登录可用。
2. V1-V5 主要只读入口均能正常访问。
3. 后端评分相关定向测试 `23/23` 通过，前端构建通过。
4. 正式方案写入、锁定保护、试算应用 gate 的关键后端边界存在。

保留风险：

1. 现有 Playwright 用例会写业务数据，且并非全部具备清理逻辑；进入 V6 阶段 1 后，应优先补可清理的隔离验收路径。
2. 方案应用/回滚、V4 调整、V5 试算应用等写入流程，本轮仅核查代码边界，未在现有业务库动态执行。
3. AI 修复“只解释与建议、不直接写正式课表”仍需专项验证。

阶段 1 建议首个实现切片：新增 `system_audit_log` 表与只读查询能力，并先接入“应用方案/回滚方案”两条正式课表写入路径。
