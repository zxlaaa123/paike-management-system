# V6_03_数据库扩展设计

## 一、设计原则

V6 数据库设计只新增治理类表，不重建 V1-V5 表，不改变已有表语义。

原则：

1. 不删除 V1-V5 字段。
2. 不修改已有业务主键。
3. 不改变正式课表写入方式。
4. 新表必须能关联学期、方案和操作人。
5. 所有治理数据可清理，不影响核心排课数据。

## 二、当前实现校准（2026-06-07）

当前代码已经实现审计日志表；其余本文件规划的 V6 治理表尚未实现：

| 规划表 | 当前状态 | 建议 |
|---|---|---|
| `system_audit_log` | 已实现：`v12_system_audit_log.sql` | 继续补齐关键写路径审计覆盖 |
| `regression_test_run` | 未实现 | 先确认是否复用 V5 的 `schedule_regression_test` |

| `data_consistency_check_run` | 未实现 | 先复用 V5 一致性检查能力，避免重复建表 |

| `api_error_code` | 未实现 | 后续错误码治理阶段再做 |

当前 V5 已有相近表：`schedule_repair_task`、`schedule_repair_suggestion`、`schedule_candidate_position`、`schedule_optimization_compare`、`schedule_consistency_check`、`schedule_regression_test`。V6 开发前必须先确认复用或扩展路径，不要直接按旧草案重复落库。

## 三、新增表总览

| 表名 | 作用 |
|---|---|
| `system_audit_log` | 系统关键操作审计日志 |
| `regression_test_run` | 回归测试批次 |
| `regression_test_case_result` | 回归测试用例结果 |
| `data_consistency_check_run` | 数据一致性检查批次 |
| `data_consistency_issue` | 数据一致性问题明细 |
| `performance_baseline_record` | 性能基线记录 |
| `api_error_code` | 后端错误码定义 |

## 四、system_audit_log

### 3.1 表作用

记录正式课表、方案、锁定、规则等关键写操作。

### 3.2 字段建议

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| operator_id | bigint | 操作人 |
| operator_name | varchar(100) | 操作人名称 |
| action_type | varchar(64) | 操作类型 |
| semester_id | bigint | 学期 ID |
| plan_id | bigint | 方案 ID |
| target_type | varchar(64) | 操作对象类型 |
| target_id | bigint | 操作对象 ID |
| before_summary | text | 修改前摘要 |
| after_summary | text | 修改后摘要 |
| success | tinyint | 是否成功 |
| error_code | varchar(64) | 失败错误码 |
| error_message | varchar(500) | 失败原因 |
| create_time | datetime | 创建时间 |

### 3.3 推荐索引

1. `(action_type, create_time)`
2. `(semester_id, create_time)`
3. `(plan_id, create_time)`
4. `(operator_id, create_time)`
