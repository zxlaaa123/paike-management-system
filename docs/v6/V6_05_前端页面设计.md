# V6_05_前端页面设计

## 一、页面设计目标

V6 前端不新增排课业务主页面，而是新增治理类页面，帮助管理员和开发者确认系统是否稳定。

页面目标：

1. 快速看到 V1-V5 回归状态。
2. 快速发现数据一致性问题。
3. 快速定位性能退化。
4. 快速追踪关键写操作。
5. 快速查看数据库迁移状态和错误码。

## 二、菜单结构

建议新增一级菜单：

```text
系统治理
├── 治理总览
├── 回归测试
├── 一致性检查
├── 性能基线
├── 审计日志
├── 数据库迁移
└── 错误码中心
```

## 三、治理总览页

### 3.1 页面路径

```text
/v6/governance
```

### 3.2 展示内容

1. 最近一次 V1-V5 回归结果。
2. 最近一次一致性检查结果。
3. 最近 24 小时关键操作数量。
4. 自动排课平均耗时。
5. 局部重排平均耗时。
6. 失败操作 Top 5 错误码。

### 3.3 视觉状态

| 状态 | 展示 |
|---|---|
| 正常 | 绿色 |
| 警告 | 黄色 |
| 失败 | 红色 |
| 未运行 | 灰色 |

## 四、回归测试页

当前状态校准（2026-06-08）：V6 第二阶段最小可交付版复用 `schedule_regression_test`，前端只做只读列表和详情，不提供运行按钮。

### 4.1 页面路径

```text
/v6/regression-tests
```

### 4.2 功能

1. 查看回归测试记录列表。
2. 按测试阶段、测试套件、状态筛选。
3. 按学期、方案筛选。
4. 分页查看记录。
5. 查看失败原因和附加信息。

### 4.3 列表字段

| 字段 | 说明 |
|---|---|
| 状态 | PASS / FAIL / BLOCKED / RUNNING |
| 测试套件 | `testSuite` |
| 测试用例 | `testCase` |
| 测试阶段 | `testStage` |
| 学期 ID | `semesterId` |
| 方案 ID | `planId` |
| 耗时 | `durationMs` |
| 执行者 | `executedBy` |
| 执行时间 | `executedAt` |
| 失败信息 | `errorMessage` |

## 五、一致性检查页

当前状态校准（2026-06-08）：V6 第三阶段最小可交付版复用 `schedule_consistency_check` 和 V5 一致性检查服务；前端提供治理只读视图和手动触发入口。

### 5.1 页面路径

```text
/v6/consistency-checks
```

### 5.2 功能

1. 查看一致性检查记录列表。
2. 按状态、检查类型、学期、方案筛选。
3. 输入修复任务 ID 与方案 ID 手动触发检查。
4. 查看检查详情。
5. 查看问题清单、严重级别和处理建议。

### 5.3 检查项展示

| 检查项 | 示例 |
|---|---|
| 学期隔离 | 方案明细学期和方案学期不一致 |
| 方案状态 | 已废弃方案仍被应用 |
| 锁定保护 | 锁定课程被局部重排修改 |
| 试算隔离 | 试算结果写入正式课表 |
| 来源追踪 | 正式课表缺少来源方案 |

## 七、审计日志页

当前状态校准（2026-06-08）：后端已有 `/api/v6/audit-logs` 与 `/api/v6/audit-logs/{id}`；前端已实现 `/v6/audit-logs` 只读页面。

### 7.1 页面路径

```text

```

2. 按学期、方案筛选。

1. 列表接口 `GET /api/v6/audit-logs` 返回 200。
2. 详情接口 `GET /api/v6/audit-logs/{id}` 返回 200。
3. 页面筛选、重置和详情弹窗可用。
4. 浏览器控制台最终无错误。

## 十、危险操作交互要求

以下操作必须二次确认：

1. 应用方案。
2. 回滚方案。
3. 应用试算方案。
4. 解除锁定。
5. 批量删除治理记录。

确认弹窗必须展示：

1. 当前学期。
2. 当前方案。
3. 影响对象数量。
4. 操作不可逆说明。
