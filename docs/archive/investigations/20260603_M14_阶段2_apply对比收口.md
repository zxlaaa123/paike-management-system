## 1. 做了什么

阶段2 比阶段1 复杂：`SchedulePlanService` 的方法有**跨模块 Java 内部调用方**（`V4ScheduleAdjustmentService`、`V5SimulationService`、`applyPlanWithAudit` 自身），改返回类型要同步这些 `result.get("xxx")` 读法。

| 端点 / 方法 | 原 Map 字段 | 新 VO |
|---|---|---|
| `SchedulePlanItemController.adjust` → `SchedulePlanService.adjustPlanItem` | 9:itemId/planId/beforeScore/afterScore/conflictFlag/conflictReason/syncFormalSchedule/scheduleId/message | `AdjustPlanResultVo` |
| `SchedulePlanController.apply` → `applyPlan` | 4:planId/semesterId/appliedCount/appliedAt | `ApplyPlanResultVo` |
| `SchedulePlanController.rollback` → `rollbackPlan` | 4（短路分支 +message） | `ApplyPlanResultVo` |
| `V5SimulationController.apply` → `V5SimulationService.apply` → `applySimulationPlan` | 4（透传 applyPlanInternal） | `ApplyPlanResultVo` |
| `SchedulePlanController.compare` → `ScheduleCompareService.compare` | 4:semesterId/plans/bestPlanId/summary（plans 元素 12 字段） | `CompareResultVo` + `ComparePlanVo` |

- **新增 VO**：4 个（`service.vo`）：`AdjustPlanResultVo`(9) / `ApplyPlanResultVo`(4+message) / `ComparePlanVo`(12) / `CompareResultVo`(4)。
- **改动文件**：4 service + 3 controller。

## 2. 关键设计决定

### 2.1 apply 与 rollback 合用一个 `ApplyPlanResultVo`（蓝图原写 2 个）
`applyPlan` / `applySimulationPlan` / `rollbackPlan` 都委派 `applyPlanInternal`（返回 4 字段、无 message），唯独 `rollbackPlan` 的「目标方案已是当前应用方案」短路分支多一个 message。
→ 用**单个 `ApplyPlanResultVo`**，message 标注 `@JsonInclude(NON_NULL)`：

- apply / applySimulation / rollback 委派分支：message=null → 省略 → JSON 仍是 4 字段；
- rollback 短路分支：message 有值 → 序列化出第 5 个字段。

**JSON 与替换前逐字节一致**，且类型自洽（rollback 两个返回分支同一类型）。提供 4 参构造器（无 message）+ 5 参构造器（@AllArgsConstructor）两种入口。

### 2.2 `ScheduleCompareService.compare` 内部聚合逻辑重写
原 `bestPlanId` 比较器与 `buildSummary` 都基于 `List<Map>` 读 `p.get("...")` / `getOrDefault("...", 0)`。改 `ComparePlanVo` 后重写为 getter 调用，并新增私有 `nullSafeInt(Integer)` 保留原 `getOrDefault(key, 0)` 的 null→0 语义（计数缺失按 0 排序，不引入新 NPE）。`totalScore` 非空（无评分回退 `BigDecimal.ZERO`），比较器 `doubleValue()` 安全。

### 2.3 内部调用方同步（阶段2 独有的改动半径）
| 调用方 | 改动 |
|---|---|
| `applyPlanWithAudit`（SchedulePlanService 内部） | `result.get("appliedCount")` → `result.getAppliedCount()`（审计 message 拼接） |
| `V4ScheduleAdjustmentService` line 123 | `Map saved` → `AdjustPlanResultVo saved`，3 处读取改 getter：`getSyncFormalSchedule()` / `getScheduleId()` / `getMessage()`（仍走原 `asLong`/`asString` 辅助器，输入对象同物、行为不变） |
| `V5SimulationService.apply()` | 返回 `Map` → `ApplyPlanResultVo`（透传，不读字段）；连带 `V5SimulationController.apply` 返回类型 |

## 3. 白送的健壮性
`compare` 原 `Map.of("bestPlanId", ...)`、apply 路径同阶段1：`Map.of` 遇 null 会 NPE，转 VO 后 null 安全，happy-path JSON 不变。
