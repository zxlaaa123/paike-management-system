# M-36 默认评分权重初始化调查

## 结论

已修复。

原问题成立：`v3_score.sql` 的默认规则权重通过当前学期驱动：

- `FROM semester s WHERE s.is_current = 1`

新库没有问题，因为 `v3_semester.sql` 会在空库插入一个 `is_current = 1` 的默认学期。但旧库如果已经有学期数据且没有任何当前学期，`v3_semester.sql` 不会新增默认学期，随后 `v3_score.sql` 也不会写入默认权重。

## 本轮处理

在 `v3_semester.sql` 的默认学期插入后增加幂等兜底：

- 如果已存在学期但没有 `is_current = 1` 的未删除学期
- 选择 `updated_at DESC, id DESC` 最新的未删除学期
- 将其设为当前学期
- 若状态为 `未开始`，同步改为 `进行中`

同步更新 `db/migration/V1__baseline.sql`，保持 baseline 与拆分脚本一致。

`v3_score.sql` 继续按当前学期初始化默认权重，不改成跨全部学期批量插入。原因是运行时代码 `SemesterService.getCurrentSemester()` 本身要求当前学期存在；先修复学期状态，比绕过当前学期语义更一致。

## 本轮验证

新增 `M36ScoreDefaultWeightInitializationTest` 锁定当前事实：

- `v3_semester.sql` 包含“无当前学期则提升最新学期”的兜底。
- `application.yml` 中 `v3_semester.sql` 先于 `v3_score.sql` 执行。
- `v3_score.sql` 仍按当前学期插入默认权重。
- `V1__baseline.sql` 在默认权重插入前包含同样的当前学期兜底。
