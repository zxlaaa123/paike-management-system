# M-30 Flyway 初始化策略调查

## 结论

已修复。

原状态：

- `pom.xml` 引入 `org.flywaydb:flyway-mysql`。
- `application.yml` 显式配置 `spring.flyway.enabled: false`。
- `db/README.md` 已说明项目有意不上 Flyway/Liquibase，初始化由 `spring.sql.init + SemesterSchemaInitializer` 组合完成。

这属于依赖和初始化策略表达不一致，不是运行时迁移故障。

## 本轮处理

- 移除 `flyway-mysql` 依赖。
- 删除 `spring.flyway.enabled: false` 配置段。
- 将“不引入 Flyway/Liquibase”的说明移到 `spring.sql.init` 注释处。

## 判断

当前项目已经形成经典 SQL 初始化路线：

- `spring.sql.init.mode: always`
- `schema-locations` 显式列出 `db/schema.sql` 与后续 `v*.sql`
- `SemesterSchemaInitializer` 只做旧库兜底
- `db/README.md` 定义三套初始化入口的执行顺序和职责边界

因此本轮不切换到 Flyway。若后续要引入 Flyway，应单独立迁移任务，处理历史脚本归档、baseline 版本、幂等脚本拆分和已有环境迁移。

## 本轮验证

新增 `M30FlywayInitializationStrategyInvestigationTest` 锁定当前事实：

- `pom.xml` 不再包含 `flyway-mysql` / `flyway-core`。
- `application.yml` 不再包含 `flyway:` 配置段。
- SQL 初始化策略和 `db/README.md` 仍然保留。
