# V7 版本需求说明

## 一、版本定位

V7 定位为“统计与展示补全版”。

V6 已完成系统治理中心的最小可交付版，但当前项目仍存在部分统计字段占位、方案展示字段缺失、自动化测试认证方式不统一等问题。V7 负责把这些不完善点做成稳定、可验收的小版本。

## 二、版本目标

1. 补齐排课方案列表中的展示字段。
2. 补齐教师工作量连续节次统计。
3. 增强首页统计，让首页能反映当前学期和关键治理状态。
4. 增强 V6 性能基线展示，支持基础趋势判断。
5. 统一 Playwright E2E 登录认证方式，减少假失败。

## 三、不做范围

1. 不引入 Flyway/Liquibase。
2. 不重写自动排课算法。
3. 不重写 V4/V5 局部重排求解器。
4. 不强制替换所有历史 `BusinessException`。
5. 不做复杂 BI 报表系统。

## 四、当前已知功能缺口

### 4.1 排课方案展示字段缺失

`SchedulePlanVo` 当前保留 `semesterName` 和 `strategyName`，但代码注释标明这两个字段恒为 `null`。这会导致前端列表只能展示 ID 或原始策略码，不利于用户理解。

### 4.2 教师连续节次统计占位

`TeacherWorkloadVo.maxContinuousPeriods` 当前恒为 `0`。教师工作量页无法反映某位教师是否一天内连续上课过多。

### 4.3 首页统计仍可增强

首页目前已有基础统计和 V3 概览，但还可以补充：

1. 当前学期排课覆盖率。
2. 未排任务数量。
3. 冲突报告数量。
4. V6 治理状态摘要。

### 4.4 性能基线缺少趋势判断

V6 性能基线中心目前有列表和汇总卡片，趋势图、慢操作提示和性能退化标记仍为后续增强。

### 4.5 E2E 登录方式不统一

新增 V6 smoke 已按 cookie 登录。旧的 `tests/stage6.spec.ts`、`tests/stage7.spec.ts`、`tests/stage9.spec.ts` 仍有 localStorage token 注入逻辑，和当前 httpOnly cookie 认证不完全一致。

## 五、成功标准

1. 用户打开排课方案列表时能看到学期名称和策略名称。
2. 教师工作量统计能显示真实连续节次。
3. 首页关键统计不再依赖占位表达。
4. V6 性能基线能支持基本趋势和慢操作识别。
5. 主要 E2E 测试使用统一 cookie 认证。
6. 后端测试、前端类型检查、前端构建和 Playwright smoke 通过。
