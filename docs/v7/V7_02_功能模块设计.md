# V7 功能模块设计

## 一、排课方案展示补全

### 1.1 问题

排课方案列表中的 `semesterName`、`strategyName` 当前为保留字段，但没有实际填充。

### 1.2 目标

1. `semesterName` 展示学期名称。
2. `strategyName` 展示策略中文名。
3. 保留原有 `semesterId`、`strategyType` 字段。
4. 不破坏前端现有类型。

### 1.3 建议实现

1. 后端在 `SchedulePlanService` 列表查询后批量加载学期。
2. 后端集中维护策略码到中文名的映射。
3. `SchedulePlanVo.fromEntity` 继续保留纯拷贝职责，关系字段由 service 填充。

## 二、教师连续节次统计

### 2.1 问题

`TeacherWorkloadVo.maxContinuousPeriods` 当前恒为 `0`。

### 2.2 目标

统计每位教师在单日内最大的连续节次数。

### 2.3 统计口径

1. 同一教师。
2. 同一天。
3. 按 `period` 或 `sortOrder` 连续判断。
4. 正式课表和方案课表都要支持。

### 2.4 示例

某教师周一第 1、2、3 大节都有课，则 `maxContinuousPeriods = 3`。

## 三、首页统计增强

### 3.1 目标

首页展示当前学期的业务状态和治理状态，帮助用户判断系统是否正常。

### 3.2 建议卡片

1. 当前学期。
2. 教学任务总数。
3. 已排任务数。
4. 未排任务数。
5. 当前应用方案。
6. 最新审计失败数。
7. 最新一致性问题数。
8. 最近性能慢操作数。

## 四、性能基线趋势增强

### 4.1 目标

在 V6 性能基线中心增加简单趋势和慢操作判断。

### 4.2 建议功能

1. 按操作类型展示最近 N 次耗时。
2. 标记超过平均值一定比例的慢操作。
3. 支持按操作类型和成功状态筛选趋势数据。

### 4.3 暂不做

1. 复杂压测平台。
2. 自动性能回归阻断 CI。
3. 多环境性能对比。

## 五、E2E 认证方式统一

### 5.1 问题

旧测试脚本仍把 token 写入 localStorage，而当前认证以 `paike_token` httpOnly cookie 为准。

### 5.2 目标

1. 提供统一 Playwright 登录 helper。
2. 旧 E2E 改用 cookie 认证。
3. 减少因认证方式不一致造成的假失败。
