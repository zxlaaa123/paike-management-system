# V9 开发阶段计划

日期：2026-06-14

总原则：四个阶段，每阶段独立可验收、可单独合入 `main`，任一阶段后停止，项目仍处于可交付状态。分支与合并纪律沿用 `V8_06`（每阶段 feature 子分支 + `--no-ff` 合入 `feature/v9-week-type`，V9 全部完成后再合入 `main`）。

本计划基于 `V9_00` 第 6 节三步走路径细化，裁决依据见 `V9_00` 第 5 节（目标真实可用 / 方案 A 仅单双周 / V8 引擎一并改 / 存量 ALL 回填 / 评分 β 独立计数 / 独立 V9 流程）。

## 关键技术选型（已倾向，各阶段启动时最终确认）

| 项 | 倾向方案 | 理由 | 最终确认节点 |
|---|---|---|---|

## 阶段 0：原型验证（止损门，3-5 天）

**目的**：在投入全链路改造前，先用最小改动验证"单双周课表的**前端展示交互**"。若交互复杂度超预期或体验不佳，及时止损，不浪费后续 3-4 周预算。

**能力边界（诚实声明，避免验收时扯皮）**：

| 本阶段**验证** | 本阶段**不验证**（留待后续阶段） |
|---|---|
| 课表单/双/全部切换控件的交互体验 | 真实单双周生成闭环（需阶段 1 的唯一键改造 + TeachingTask 输入源） |
| 同一时段多条 plan_item（不同任务、不同 weekType）的展示与过滤 | 同一任务同时段 ODD+EVEN 两条（被 `uk_plan_task_slot` 挡住，阶段 1 才放开） |
| weekType 字段从后端透传到前端的查询链路 | 冲突检测、评分、导出、V8 引擎（分别属阶段 1/2/3） |

**范围限制**：只动前端展示 + 后端查询透传，**不碰 V8 引擎、不碰数据模型、不碰唯一键、不接 TeachingTask 输入**。weekType 通过测试数据手动注入。

**产出**

- 前端 `TimetableGrid.vue`：加"单周/双周/全部"切换控件，按 weekType 过滤 items
- `SchedulePlanDetailView.vue`：明细列表展示 weekType 列
- 后端 `TimetableService` 查询 VO 透传 weekType（plan_item 已有该字段，仅查询层透传到前端）
- 测试数据脚本：手动 INSERT 两条**不同任务**（一个 weekType=ODD、一个 weekType=EVEN）落在同一时段的 plan_item，验证前端切换效果。**不碰唯一键**——本阶段只验证不同任务共槽的切换交互。

**验收（Go/No-Go 判定）**

- 切换控件能正确过滤单/双/全部三种视图

- **主观体验判定**（用户确认）：单双周课表的展示方式是否符合预期、是否清晰可辨

**Go/No-Go**：用户确认交互体验可接受 → 进入阶段 1；否则停止 V9，保留原型作为设计参考。

**说明：阶段 1 引擎版的 stub 行为（明确语义，验收时按此断言）**

V8 引擎的周次扩展涉及 TimeSlotData 改造（方案 X），是阶段 3 的工作。阶段 1 让引擎**显式拒绝**非 ALL 任务，**不是降级为 ALL 静默处理**：

- **行为定义**：`EngineContextLoader` 装载时检测到 `task.weekType != "ALL"` 的任务 → 该任务不进入引擎求解，直接落 `schedule_unassigned_task`，reasonCode = `WEEK_TYPE_NOT_SUPPORTED_BY_SOLVER_V8`，reasonMessage = "V8 引擎暂不支持单双周任务，请使用其他策略或等待 V9.2"。
- **为什么选拒绝而非降级**：降级为 ALL 会让用户误以为 V8 支持单双周但排错了（静默错误）；显式拒绝让用户清楚知道能力边界，可选别的策略重排。
- **测试断言**（阶段 1 有效）：SOLVER_V8 生成含 ODD/EVEN 任务的方案时，这些任务 100% 落 unassigned，且 reasonCode 为上述值；ALL 任务正常排课。
- **阶段 3 启用后**：此 stub 移除，reasonCode 弃用（或改为真正的排课失败原因）。

这样阶段 1 结束时**旧四策略完整支持单双周，V8 引擎诚实拒绝单双周任务**，是个可交付的中间态。

**验收（R1 红线）**

- `WeekTypeConflictMatrixTest` 9/9 通过
- `ConflictDetectorWeekTypePairTest` 逐格一致，0 偏差
- 构造"单双周共用时段"用例：教师周一 1-2 节 ODD 体育 + EVEN 思政，两策略都能排下且互不冲突

## 各阶段共同的完成定义（DoD）

1. `mvn test` 后端全绿（含本阶段新增测试）。

3. `npm test` 现有 57 E2E 全绿（不回归）。
4. 不改动 `V9_00` 第 5 节已裁决项；如确需变更，停止开发，先更新文档并经用户确认。
5. 提交信息与分支规范沿用 `V8_06`（feature 子分支 + `--no-ff`，禁止 `git add -A`）。
