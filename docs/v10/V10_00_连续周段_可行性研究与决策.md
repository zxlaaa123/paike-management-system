# V10 可行性研究：连续周段支持

## 0. 一句话结论

建议做。V10 不替换 V9 的 `week_type` 三值模型，而是在 `ALL / ODD / EVEN` 上叠加 `start_week` / `end_week` 连续周段字段，统一用“周段相交 && 周型相交”判定同槽冲突。

先做后端闭环和导出显示，再补前端编辑体验。不要直接上 JSON 周模式或任意周集合。

## 1. 为什么要做

V9 已支持全周、单周、双周，但真实课表仍有常见缺口：

- 第 1-8 周上某门课，第 9-16 周换另一门课。
- 实验课只在第 5-12 周开。
- 同一教师、班级、教室在同一节次可被不同周段复用。
- 导出课表需要显示“1-8周”“9-16周”，否则同槽课程会被误读为冲突。

当前 V9 的 `ODD + EVEN` 共槽已经证明“同一物理时段多条记录可合法共存”。V10 是把这个能力从单双周扩到连续周段。

## 2. 现状事实

| 层面 | 当前状态 |
|---|---|
| 数据模型 | `schedule`、`teaching_task`、`schedule_plan_item` 已有 `week_type` |
| 周型语义 | `WeekTypeSupport` 固定支持 `ALL / ODD / EVEN` |
| 唯一键 | V9 已把 `week_type` 纳入正式课表与方案项唯一键 |
| 冲突检测 | 核心语义是 `WeekTypeSupport.overlap(a, b)` |
| 评分 | `WeekTypeSupport.countableWeekTypes()` 把 `ALL` 展开为 `ODD + EVEN` |
| 导出 | `TimetableService` 使用 `WeekTypeSupport.displayLabel()` 显示 `[单] / [双]` |
| 学期 | `Semester` 有开始/结束日期，但没有显式总周数字段 |

结论：V10 需要新增“周段”维度，但不能只改字段。冲突检测、评分、导出、唯一键、迁移脚本必须同步定义。

## 3. 推荐方案

### 3.1 数据表达

保留：

- `week_type VARCHAR(20) NOT NULL DEFAULT 'ALL'`

新增：

- `start_week INT NOT NULL DEFAULT 1`
- `end_week INT NOT NULL DEFAULT 20`

含义：

- `start_week`、`end_week` 表示连续自然周闭区间。
- `week_type=ALL` 表示区间内每周都上。
- `week_type=ODD` 表示区间内只取奇数周。
- `week_type=EVEN` 表示区间内只取偶数周。

示例：

| 表达 | 语义 |
|---|---|
| `ALL, 1, 20` | 1-20 周每周 |
| `ODD, 1, 20` | 1-20 周内单周 |
| `EVEN, 1, 20` | 1-20 周内双周 |
| `ALL, 1, 8` | 1-8 周每周 |
| `ODD, 5, 12` | 5-12 周内单周，即 5、7、9、11 周 |

### 3.2 统一冲突语义

两条排课同一物理时段下，只有同时满足以下条件才冲突：

1. 教师 / 班级 / 教室资源相同。
2. 实际自然周集合相交：`activeWeeks(a.weekType, a.startWeek, a.endWeek) ∩ activeWeeks(b.weekType, b.startWeek, b.endWeek)` 非空。

因此：

- `ALL 1-8` 与 `ALL 9-16` 不冲突。
- `ALL 1-8` 与 `ODD 5-12` 冲突，重叠自然周为 5、7。
- `ODD 1-8` 与 `EVEN 1-8` 不冲突。
- `ODD 1-8` 与 `EVEN 8-12` 不冲突，区间端点相交在第 8 周，但第 8 周不是单周。
- `ALL 8-8` 与 `ODD 1-9` 不冲突，重叠区间只有第 8 周，实际周集合无交集。
- `ODD 1-9` 与 `ODD 8-12` 冲突，重叠自然周为 9。

注意：不能继续用 V9 的纯三值矩阵直接判断，也不能只判断 `start_week/end_week` 区间端点。V10 必须计算实际自然周集合交集。

### 3.3 命名建议

新增工具类：

- `WeekPatternSupport`

职责：

- 归一化 `startWeek / endWeek / weekType`
- 生成 `activeWeeks` 或位图，建议内部使用 `long` bit mask 覆盖 1-63 周
- 判断 `overlap(aType, aStart, aEnd, bType, bStart, bEnd)`
- 生成导出标签
- 为评分提供可计数周集合或周数

`WeekTypeSupport` 可以保留，作为 V9 三值工具。V10 新逻辑不要继续塞进 `WeekTypeSupport`，否则类名和职责会失真。

## 4. 不推荐方案

### 4.1 直接把 `week_type` 扩成字符串模式

例如 `1-8_ODD`、`1,3,5,7`、`ALL:1-8`。

不建议。原因：

- 数据库约束和索引不可读。
- 查询、导出、校验都要解析字符串。
- 错误值无法靠简单字段校验拦截。
- 后续前端编辑更难做。

### 4.2 用 JSON 表达任意周集合

例如 `week_pattern = {"weeks":[1,3,5,7]}`。

V10 不建议。原因：

- 当前需求是连续周段，不是任意周集合。
- MySQL 索引、唯一键、迁移、冲突检测都更复杂。
- 测试面会明显扩大，收益不匹配。

### 4.3 物理复制每一周课表

例如一条 1-8 周课程落成 8 条 `schedule`。

不建议作为主模型。原因：

- 正式课表记录膨胀。
- 调课、锁定、审计、导出会出现主从记录关系问题。
- 删除和软删除更容易出错。

可作为临时计算视图或测试展开口径，不作为持久化设计。

## 5. 数据库影响

### 5.1 正式课表

`schedule` 新增：

- `start_week INT NOT NULL DEFAULT 1`
- `end_week INT NOT NULL DEFAULT 20`

现有唯一键不能只追加 `start_week / end_week` 后结束。原因：`1-8` 与 `5-12` 即使键值不同，也可能语义冲突。数据库唯一键只能挡完全同段，挡不住区间重叠。

建议：

- 唯一键保留“精确重复”防线。
- 语义冲突统一由服务层 / 引擎层判定。
- 迁移脚本必须幂等。

### 5.2 教学任务

`teaching_task` 新增：

- `start_week INT NOT NULL DEFAULT 1`
- `end_week INT NOT NULL DEFAULT 20`

输入校验：

- `start_week >= 1`
- `end_week >= start_week`
- `end_week <= semesterWeekCount`

`semesterWeekCount` V10 可以先用默认 20。是否从学期开始/结束日期推导，单独决策，不阻塞主线。

### 5.3 方案项

`schedule_plan_item` 新增同名字段：

- `start_week`
- `end_week`

方案项必须保存生成时的周段快照，不能只依赖教学任务当前值。否则任务被改后，历史方案含义会漂移。

## 6. 后端影响面

| 模块 | 改动 |
|---|---|
| Entity / DTO / VO | `Schedule`、`TeachingTask`、`SchedulePlanItem` 增加周段字段 |
| Mapper / SQL | 查询、插入、导出字段补齐 |
| 入参校验 | 教学任务创建/更新校验周段 |
| 冲突检测 | 从 `WeekTypeSupport.overlap` 升级为周段+周型相交 |
| V8 引擎 | 内存模型携带 `startWeek/endWeek`，Detector 统一判断 |
| 评分 | 负荷统计按实际自然周或周段权重计数 |
| 导出 | cell 中展示课程名 + 周段 + 单双周标记 |
| V4/V5 校验 | 冲突报告、试算、事务边界测试补周段用例 |

## 7. 导出显示裁决

推荐格式：

- 全周整学期：`高等数学`
- 单双周整学期：`体育[单]`、`体育[双]`
- 连续周段：`大学英语[1-8周]`
- 周段 + 单双周：`实验课[5-12周/单]`

同一 cell 多门课：

- 每门课独立一行。
- 不再静默覆盖。
- 排序按 `start_week`、`end_week`、`week_type`、课程名。

## 8. 评分裁决

V10 评分不要只按 `ODD / EVEN` 两桶计数。

推荐：

- 日负荷硬约束：按实际自然周展开判断。
- 软约束均衡：可先按“周数权重”统计，例如 1-8 周全周课计 8，5-12 周单周课计 4。
- 在线增量评分与离线 rescore 必须共用同一工具方法，避免 V8/V9 曾经防过的双轨漂移。

## 9. 阶段计划

### 阶段 0：原型与红线测试

- 新建 `WeekPatternSupport`。
- 单测覆盖周段+周型冲突矩阵。
- 明确 `ODD 1-8` 与 `EVEN 8-12` 冲突这类边界。

完成标准：

- 周段相交、周型相交、边界周交叉测试通过。

### 阶段 1：数据模型与输入源

- 数据库迁移脚本。
- Entity / DTO / VO 字段补齐。
- 教学任务创建/更新校验。
- 存量数据默认 `1-20`。

完成标准：

- 原有 V9 数据保持等价。
- CRUD 测试覆盖默认值与非法周段。

### 阶段 2：冲突检测与生成闭环

- DB 版冲突检测接入 `WeekPatternSupport`。
- V8 内存 Detector 接入同源判断。
- 生成、落库、正式课表查询透传周段。

完成标准：

- 同槽不同周段可共存。
- 同槽周段重叠被拦截。
- DB 链路与 V8 链路对拍一致。

### 阶段 3：评分与导出

- 在线增量评分、离线 rescore 共用周段计数。
- Excel 导出多课程 cell 周段展示。
- 网格展示透传。

完成标准：

- 不出现静默覆盖。
- 旧 `ALL/ODD/EVEN` 导出表现不回退。

### 阶段 4：前端最小编辑闭环

- 教学任务表单增加起止周。
- 默认 1-20。
- 列表展示周段。
- 先不做复杂日历式周选择器。

完成标准：

- 管理员能创建 1-8 周、9-16 周任务。
- 能通过导出看到正确周段。

## 10. 测试清单

| 类型 | 必测点 |
|---|---|
| 单元 | `WeekPatternSupport` 周段+周型矩阵 |
| Mapper | `start_week/end_week` 插入、查询、默认值 |
| Service | 教学任务校验、正式课表冲突、软删除后可复用 |
| 引擎 | V8 Detector 与 DB 检测对拍 |
| 评分 | 在线增量与离线 rescore 一致 |
| 导出 | 同 cell 多课程、周段标签、单双周标签 |
| 回归 | V9 `ALL/ODD/EVEN` 全量保留 |
| 全量 | `mvn test`，必要时 MySQL 使用本地 `root / 123456` |

## 11. 风险

| 风险 | 等级 | 处理 |
|---|---|---|
| 唯一键无法表达区间重叠 | 高 | 不依赖唯一键做语义冲突，服务层统一判断 |
| V9 三值矩阵被误复用 | 高 | 新建 `WeekPatternSupport`，红线测试覆盖边界 |
| 评分双轨漂移 | 中 | 在线/离线共用计数工具 |
| 导出再次静默覆盖 | 中 | 多课程 cell 追加行，测试读取 Excel 断言 |
| 学期周数来源不清 | 中 | V10 初期默认 20，后续再引入显式 `week_count` |
| 前端控件复杂化 | 低 | 先用两个数字输入，暂缓高级选择器 |

## 12. 当前裁决

V10 采用：

- `week_type + start_week + end_week`
- 连续周段，不做任意周集合
- 冲突判定：资源相同 && 实际自然周集合相交
- 新增 `WeekPatternSupport`
- 先后端闭环，再前端增强
