# V10 开发阶段计划：连续周段支持

## 0. 执行原则

- 先加红线测试，再改生产代码。
- 先统一周模式工具，再改各业务链。
- 所有链路使用同一个 `WeekPatternSupport.overlap`，冲突以“实际自然周集合相交”为准。
- 不提交大杂烩。每阶段改动可独立回归。
- 本阶段不做任意周集合、不做 JSON 周模式、不做学期周数后台配置。

## 1. 阶段 0：周模式原型与红线测试

目标：先证明周段+周型语义正确，避免后续各链路各写一套判断。

新增：

- `backend/src/main/java/com/paike/scheduler/service/WeekPatternSupport.java`
- `backend/src/test/java/com/paike/scheduler/service/WeekPatternSupportTest.java`

核心实现：

- `activeWeekMask`
- `overlap`
- `activeWeekCount`
- `displayLabel`
- `validateRange`

红线用例：

| A | B | 结果 |
|---|---|---|
| `ALL 1-8` | `ALL 9-16` | 不冲突 |
| `ALL 1-8` | `ODD 5-12` | 冲突 |
| `ODD 1-8` | `EVEN 1-8` | 不冲突 |
| `ODD 1-8` | `EVEN 8-12` | 不冲突 |
| `ALL 8-8` | `ODD 1-9` | 不冲突 |
| `ODD 1-9` | `ODD 8-12` | 冲突 |

完成定义：

- 工具单测通过。
- 文档中的冲突矩阵和测试一致。

## 3. 阶段 2：手动排课与方案冲突链

目标：DB 版手动排课、方案内冲突刷新、冲突报告口径一致。

改造入口：

- `ScheduleConflictService.checkConflict`
- `ScheduleMapper.selectDailyConflictCounts`
- `SchedulePlanService.buildPeerConflictReasons`
- `SchedulePlanService.addGroupedConflictReasons`
- `ScheduleConflictReportService.detectTeacherConflicts`
- `ScheduleConflictReportService.detectClassConflicts`
- `ScheduleConflictReportService.detectClassroomConflicts`
- `ScheduleConflictReportService.detectTeacherDailyOverload`
- `ScheduleConflictReportService.detectClassDailyOverload`

建议实现：

- 同 timeSlot 的资源冲突先粗查，再用 `WeekPatternSupport.overlap` 过滤。
- 每日上限不继续只按 `week_type` SQL 分支聚合；服务层按实际周集合过滤更稳。
- `ScheduleConflictReportService` 不能只看 group size，必须判断组内真冲突 pair。

补测：

- `ScheduleConflictServiceTest`
- `SchedulePlanServiceTest`
- `ScheduleConflictReportServiceTest`

完成定义：

- 同资源同槽不同实际周集合不报冲突。
- 同资源同槽实际周集合相交必报冲突。
- 方案应用前冲突刷新和手动排课结论一致。

## 5. 阶段 4：V8 引擎与自动生成

目标：自动排课生成的候选、冲突检测、落库都支持周段。

改造入口：

- `EngineTask`
- `EngineContextLoader`
- `InMemoryConflictDetector`
- `BacktrackingSolver`
- `NeighborOperator`
- `ObjectiveFunction.assignmentToItem`
- `V3ScheduleGenerateService` 生成 plan item 链路

关键裁决：

- `Assignment` 暂不加周段字段，周段属于 task。
- 当前 V9 slot 翻倍机制不能作为 V10 硬冲突依据。
- `InMemoryConflictDetector` 需要在同物理时段资源列表中做 `WeekPatternSupport.overlap`。
- 如果继续保留 ODD/EVEN 逻辑 slot，必须保证 `ALL 1-8` 与 `ALL 9-16` 不被 false positive。

补测：

- `InMemoryConflictDetectorWeekRangeTest`
- `EngineWeekRangeIntegrationTest`
- `ConflictDetectorPairTest`
- `V9WeekTypeBenchmarkTest` 继续跑，防 V9 回退

完成定义：

- V8 可生成混合周段任务。
- DB 版冲突检测与 InMemory Detector 对拍一致。
- 同 seed 可复现。

## 6. 阶段 5：评分链

目标：在线、离线、引擎三方评分口径一致。

改造入口：

- `WeekPatternSupport.activeWeekCount`
- `ScoringFunctions`
- `DeltaPenaltyScorer`
- `ObjectiveFunction`
- `IncrementalPenaltyState`
- `ScheduleScoreService`

建议口径：

- 日负荷、连续上课、同课同日按实际周集合展开或按 mask 聚合。
- `activeWeekCount` 可作为权重，但不能让 `ALL 1-20` 破坏 V9 baseline。
- 在线增量和离线 rescore 必须共用工具方法。

补测：

- `ScoringWeekTypeConsistencyTest` 扩展为 week range 用例。
- `AnnealingOptimizerTest` 保持硬约束。
- `ScheduleScoreServiceTest` 增加周段权重场景。

完成定义：

- 增量评分与全量评分一致。
- V8 Objective 与 ScheduleScoreService 一致。
- 旧纯 ALL 数据分数不回退。

前端：

- `frontend/src/api/timetable.ts`
- `frontend/src/components/TimetableGrid.vue`

- 周段+单双周显示 `[5-12周/单]`。
- 同 cell 多课程继续用分隔符，不覆盖。
