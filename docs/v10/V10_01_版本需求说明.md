# V10 版本需求说明：连续周段支持

## 1. 一句话目标

在 V9 `ALL / ODD / EVEN` 周型能力上，增加连续周段 `start_week / end_week`，让同一物理时段可以按实际自然周集合复用教师、班级、教室，并保证冲突检测、生成、评分、导出一致。

## 2. 调查依据

本说明基于当前代码结构调查，不按想象写需求。

| 领域 | 当前关键文件 / 方法 | 结论 |
|---|---|---|
| 周型工具 | `backend/src/main/java/com/paike/scheduler/service/WeekTypeSupport.java` | 只支持 `ALL/ODD/EVEN` 三值矩阵 |
| 正式课表冲突 | `ScheduleConflictService.checkConflict` | 教师/班级用任务 `weekType`，教室用 schedule `weekType` |
| 方案内冲突 | `SchedulePlanService.buildPeerConflictReasons` / `addGroupedConflictReasons` | 同资源同时间分组后用 `WeekTypeSupport.overlap` 过滤 |
| 冲突报告 | `ScheduleConflictReportService.detectTeacherConflicts` 等 | 当前按资源+timeSlot 直接分组，未过滤 `weekType` |
| V4 风险 | `V4ScheduleRiskService.detectSlotConflicts` | 已按 `WeekTypeSupport.overlap` 过滤 |
| V5 校验 | `V5ConsistencyCheckService.checkHardConflicts` | period overlap + `WeekTypeSupport.overlap` |
| V6 回归 | `V6RegressionTestService.scanResourceConflict` | 同资源同物理时段下检测 `WeekTypeSupport.overlap` |
| V8 引擎 | `EngineContextLoader` / `InMemoryConflictDetector` / `BacktrackingSolver` | V9 用 slot 物理翻倍表达 ODD/EVEN，ALL 扩散到配对 slot |
| 评分 | `DeltaPenaltyScorer` / `ObjectiveFunction` / `IncrementalPenaltyState` | 通过 `countableWeekTypes` 把 ALL 展开到 ODD+EVEN 两桶 |
| 导出 | `TimetableService.buildCellText` | 同 cell 多条用 `---` 分隔，课程名加 `[单]/[双]` |
| 前端任务 | `frontend/src/api/teachingTask.ts` / `TeachingTaskView.vue` | 表单和类型只有 `weekType`，无起止周 |

## 3. 已锁定决策

1. 保留 `week_type`，新增 `start_week`、`end_week`。
2. V10 只做连续周段，不做任意周集合。
3. 冲突判断以实际自然周集合交集为准。
4. 新增 `WeekPatternSupport`，不要把周段逻辑继续塞进 `WeekTypeSupport`。
5. 存量数据默认 `start_week=1`、`end_week=20`。
6. V10 初期默认学期周数为 20，不在本阶段强制新增 `semester.week_count`。
7. 方案项必须保存周段快照，不能运行时只查教学任务。
8. 先后端闭环，再做前端编辑增强。

## 4. 术语

| 术语 | 含义 |
|---|---|
| 周型 | `week_type`，合法值 `ALL/ODD/EVEN` |
| 周段 | `start_week` 到 `end_week` 的闭区间 |
| 实际自然周集合 | 周型过滤后的自然周集合 |
| 周模式 | `week_type + start_week + end_week` 的组合 |

示例：

| 周模式 | 实际自然周集合 |
|---|---|
| `ALL, 1, 4` | 1,2,3,4 |
| `ODD, 1, 8` | 1,3,5,7 |
| `EVEN, 8, 12` | 8,10,12 |

## 5. 功能需求

### R1 数据模型

以下表新增字段：

- `teaching_task.start_week`
- `teaching_task.end_week`
- `schedule_plan_item.start_week`
- `schedule_plan_item.end_week`
- `schedule.start_week`
- `schedule.end_week`

字段要求：

- `INT NOT NULL DEFAULT 1 / 20`
- 迁移脚本幂等
- 历史数据迁移后等价于 V9 全学期行为

### R2 周模式工具

新增 `WeekPatternSupport`。

必须提供：

- `normalizeWeekType(String)`
- `normalizeStartWeek(Integer)`
- `normalizeEndWeek(Integer)`
- `validateRange(startWeek, endWeek, maxWeek)`
- `activeWeekMask(weekType, startWeek, endWeek)`
- `overlap(aType, aStart, aEnd, bType, bStart, bEnd)`
- `activeWeekCount(weekType, startWeek, endWeek)`
- `displayLabel(weekType, startWeek, endWeek, defaultStart, defaultEnd)`

建议内部用 `long` bit mask 表达 1-63 周。当前默认 20 周足够，性能和测试都简单。

### R3 教学任务输入源

后端：

- `TeachingTaskController.TaskForm` 增加 `startWeek/endWeek`。
- `TeachingTaskService.create/update` 校验并写入周段。
- `TeachingTaskVo.fromEntity` 透传字段。
- 非法周段返回 400。

前端：

- `frontend/src/api/teachingTask.ts` 增加字段。
- `TeachingTaskView.vue` 表单默认 `1-20`。
- 列表显示周段标签。

### R4 手动排课冲突

`ScheduleConflictService.checkConflict` 必须从当前任务和已有 schedule 行拿完整周模式。

冲突规则：

- 同教师同 timeSlot 且实际自然周集合相交：冲突。
- 同班级同 timeSlot 且实际自然周集合相交：冲突。
- 同教室同 timeSlot 且实际自然周集合相交：冲突。

每日上限和同课同日：

- 不能继续只靠 `ScheduleMapper.selectDailyConflictCounts` 的 `week_type` 条件。
- V10 应按当天所有候选 schedule 做周模式过滤后计数。
- 若保留 SQL 聚合，必须能表达实际周集合相交，否则改为服务层聚合。

### R5 方案项与应用正式课表

生成方案项时：

- 从任务快照写入 `SchedulePlanItem.startWeek/endWeek`。
- `weekType` 仍归一化写入。

应用方案时：

- `SchedulePlanService.applyPlanInternal` 从 `plan_item` 透传 `weekType/startWeek/endWeek` 到 `schedule`。
- 已应用方案调整时，`syncAppliedSchedule` 同步周段。

V10 不要求在方案调整弹窗里编辑周段。调整只改时间和教室，周段跟随原 plan item。

### R6 方案内冲突刷新

`SchedulePlanService.refreshPlanConflictState` 下的 peer 冲突判断必须升级。

当前入口：

- `buildPeerConflictReasons`
- `addGroupedConflictReasons`

要求：

- 仍按 weekday/startPeriod 做粗分组。
- 同组同资源下，只在 `WeekPatternSupport.overlap` 为 true 时标记冲突。
- 不同周段无交集时允许共槽。

### R7 冲突报告与一致性链

以下链路必须同步升级：

- `ScheduleConflictReportService.detectTeacherConflicts`
- `ScheduleConflictReportService.detectClassConflicts`
- `ScheduleConflictReportService.detectClassroomConflicts`
- `ScheduleConflictReportService.detectTeacherDailyOverload`
- `ScheduleConflictReportService.detectClassDailyOverload`
- `V4ScheduleRiskService.detectSlotConflicts`
- `V5ConsistencyCheckService.checkHardConflicts`
- `V6RegressionTestService.scanResourceConflict`

其中 `ScheduleConflictReportService` 当前没有周型过滤，是 V10 高风险点。

### R8 V8 引擎

引擎必须携带周段：

- `EngineTask` 增加 `startWeek/endWeek`。
- `EngineContextLoader` 从 `TeachingTask` 装载周段。
- `Assignment` 是否增加周段字段需评估；推荐周段属于 task，不属于 assignment。
- `ObjectiveFunction.assignmentToItem` 写出 `startWeek/endWeek`。

`InMemoryConflictDetector` 必须基于实际周集合判断同槽资源冲突。

V9 slot 物理翻倍只适合 `ODD/EVEN`，不能完整表达连续周段：

- `ALL 1-8` 与 `ALL 9-16` 当前会被错误视为冲突。
- `ODD 1-8` 与 `EVEN 8-12` 当前可能被错误理解为只看区间端点或只看周型。

V10 可以保留翻倍 slot 作为候选生成细节，但硬冲突裁决必须以 `WeekPatternSupport.overlap` 为准。

### R9 评分

在线增量、离线 rescore、V8 Objective 必须共用同一周模式计数口径。

要求：

- `activeWeekCount` 作为权重参与负荷统计。
- 同一天同资源统计要按实际自然周集合展开或按 mask 聚合。
- `ALL 1-20` 在默认 20 周下不得破坏 V9 全周回归。

受影响文件：

- `DeltaPenaltyScorer`
- `ScoringFunctions`
- `ObjectiveFunction`
- `IncrementalPenaltyState`
- `ScheduleScoreService`

### R10 导出与网格

`TimetableService` 要透传并展示周段：

- `buildTimetableVo` 设置 `startWeek/endWeek`。
- `buildCellText` 使用 `WeekPatternSupport.displayLabel`。
- 同 cell 多条继续用 `---` 分隔。

展示规则：

- `ALL 1-20`：不加标签。
- `ODD 1-20`：`[单]`。
- `EVEN 1-20`：`[双]`。
- `ALL 1-8`：`[1-8周]`。
- `ODD 5-12`：`[5-12周/单]`。

### R11 API 与兼容

所有新增字段允许旧客户端不传：

- create 默认 1-20。
- update 若不传周段，保持原值或按明确策略默认 1-20；推荐保持原值。
- VO 总是返回规范化后的周段。

### R12 非目标

V10 不做：

- 任意周集合 UI。
- JSON 周模式。
- 学期周数后台管理。
- 批量拆课为每周独立记录。
- 大规模重构 `TimeSlot` 模型。
- 方案调整界面编辑周段。

## 6. 验收口径

V10 完成必须满足：

1. `ALL 1-8` 与 `ALL 9-16` 同槽同资源可共存。
2. `ALL 1-8` 与 `ODD 5-12` 同槽同资源被拦截。
3. `ODD 1-8` 与 `EVEN 8-12` 同槽同资源可共存。
4. 手动排课、自动生成、方案应用、冲突报告、V4/V5/V6 校验结论一致。
5. 导出不静默覆盖，同 cell 多课程都可见。
6. V9 旧数据和旧测试不回退。
