# V5_05_前端页面设计

# 排课系统 V5 前端页面设计

> 版本：V5 版本  
> 文档类型：前端页面设计  
> 适用项目：排课系统仿真 / 高校排课管理系统  
> V5 定位：约束驱动的局部重排与智能修复优化版  
> 前置基础：V3 学期与排课方案页面、V4 排课质量分析与智能辅助优化页面、V5 API 接口设计  
> 重要原则：V5 前端是增量扩展，不重写 V3/V4 页面；所有修复和局部重排必须先生成试算方案，不能在前端直接修改正式课表。

---

## 一、文档说明

本文档用于指导排课系统 V5 版本的前端页面开发。

V5 版本不是重新设计一个排课系统前端，也不是推翻 V3、V4 已经形成的页面体系，而是在已有页面基础上新增“修复、试算、对比、检查、回归”的操作入口。

V5 前端重点解决以下问题：

1. 如何从 V4 风险诊断结果进入 V5 修复流程；
2. 如何创建排课修复任务；
3. 如何展示系统生成的修复建议；
4. 如何展示可替换时间、教室和组合候选位置；
5. 如何基于建议或候选位置生成试算方案；
6. 如何展示修复前后评分、风险、课表变化对比；
7. 如何支持锁定课程后的局部重排试算；
8. 如何展示数据一致性检查和系统健康检查；
9. 如何展示回归测试记录；
10. 如何使用 AI 辅助解释修复建议，但不让 AI 直接修改课表。

V5 前端的核心思想是：

```text
V4 发现风险
  ↓
V5 创建修复任务
  ↓
生成修复建议 / 候选位置
  ↓
生成试算方案
  ↓
展示优化前后对比
  ↓
用户确认后再走方案应用流程
```

## 三、前端设计总原则

### 3.1 不重写旧页面

V5 前端必须遵守：

```text
不重写 V3 多方案生成页面；
不重写 V3 方案详情页面；
不重写 V3 方案应用和回滚页面；
不重写 V4 质量分析和风险诊断页面；
不重写 V4 课程锁定页面；
不重写 V4 报告页面。
```

V5 只通过新增入口、新增页面、新增弹窗进行扩展。

---

### 3.2 修复流程必须安全

V5 所有修复相关页面都必须明确区分：

```text
修复建议：只是建议，不修改课表；
候选位置：只是可选位置，不修改课表；
试算方案：生成新方案，不直接覆盖正式课表；
应用方案：必须用户确认后走正式应用流程。
```

前端文案必须避免误导用户，例如不要把“生成试算方案”写成“立即修复课表”。

---

### 3.3 分析和检查页面默认只读

以下页面默认只读：

1. 约束规则查看页面；
2. 修复任务详情的历史信息区；
3. 修复建议详情；
4. 候选位置评估结果；
5. 优化前后对比；
6. 试算方案变更明细；
7. 数据一致性检查结果；
8. 回归测试记录；
9. AI 修复解释。

只读页面不能直接修改正式课表。

---

### 3.4 危险操作必须二次确认

以下操作必须有二次确认弹窗：

1. 创建修复任务；
2. 重新生成修复建议；
3. 重新生成候选位置；
4. 选择修复建议；
5. 忽略修复建议；
6. 基于建议生成试算方案；
7. 基于候选位置生成试算方案；
8. 创建局部重排试算方案；
9. 废弃试算方案；
10. 应用试算方案；
11. 标记数据检查问题状态；
12. 保存回归测试结果。

其中“应用试算方案”必须使用高强度确认文案：

```text
本操作会将试算方案应用为当前学期正式课表。应用前请确认优化前后对比结果。
```

---

### 3.5 所有核心判断以后端为准

前端可以做基础表单校验，但不能代替后端业务校验。

以下判断必须以后端接口返回为准：

1. 是否存在硬约束冲突；
2. 候选位置是否可用；
3. 锁定课程是否会被影响；
4. 试算方案是否可应用；
5. 修复建议是否推荐采用；
6. 数据一致性检查是否通过；
7. 回归测试是否通过。

## 七、页面一：V5 修复任务列表页

### 7.1 页面名称

```text
修复任务
```

建议文件：

```text
frontend/src/views/v5/RepairTaskList.vue
```

### 7.2 页面目标

集中展示当前学期下的排课修复任务。

该页面是 V5 的主入口。

### 7.3 页面布局

```text
顶部说明区
  - V5 智能修复说明
  - 当前学期
  - 当前应用方案

筛选区
  - 学期
  - 来源类型：正式课表 / 排课方案
  - 修复模式
  - 任务状态
  - 关键词
  - 查询按钮
  - 重置按钮
  - 新建修复任务按钮

统计卡片区
  - 任务总数
  - 待处理任务
  - 已生成建议任务
  - 已生成试算任务
  - 已完成任务

任务表格区
  - 任务编号
  - 任务名称
  - 修复模式
  - 来源对象
  - 关联风险数
  - 锁定课程数
  - 当前状态
  - 创建时间
  - 操作
```

### 7.4 操作按钮

每行建议包含：

```text
详情
生成建议
候选位置
生成试算
优化对比
废弃
```

按钮显示规则：

1. `生成建议`：仅任务处于待分析或建议失败时显示；
2. `候选位置`：任务已创建后可显示；
3. `生成试算`：至少有一个建议或候选位置后显示；
4. `优化对比`：已有试算方案后显示；
5. `废弃`：已完成任务不建议再显示。

### 7.5 主要接口

```http
GET  /api/v5/schedule-repair-tasks
POST /api/v5/schedule-repair-tasks/{taskId}/abandon
GET  /api/v5/regression-tests/summary
```

### 7.6 注意事项

1. 默认按当前学期过滤；
2. 如果没有当前学期，提示先设置当前学期；
3. 不要在列表页直接应用试算方案；
4. 列表页只作为任务入口。

## 八、页面二：创建修复任务弹窗

### 8.1 弹窗名称

```text
创建修复任务
```

可以作为 `RepairTaskList.vue` 的子组件：

```text
frontend/src/views/v5/components/CreateRepairTaskDialog.vue
```

### 8.2 弹窗目标

让用户选择修复来源、修复模式、修复范围和是否保护锁定课程。

### 8.3 表单字段

| 字段 | 说明 | 组件建议 |
|---|---|---|
| taskName | 修复任务名称 | el-input |
| semesterId | 所属学期 | el-select，默认当前学期 |
| sourceType | 来源类型 | el-radio |
| sourcePlanId | 来源方案 | el-select |
| sourceScheduleId | 来源正式课表 | el-select / 自动识别 |
| repairMode | 修复模式 | el-select |
| scopeType | 修复范围类型 | el-select |
| selectedRiskIds | 关联风险 | el-table 多选 |
| selectedItemIds | 参与修复课程 | el-table 多选 |
| protectLockedItems | 是否保护锁定课程 | el-switch |
| remark | 备注 | el-input textarea |

### 8.4 修复模式建议

```text
单风险修复
多风险批量修复
班级局部重排
教师局部重排
教室局部重排
时间段局部重排
正式课表试算优化
方案试算优化
```

### 8.5 主要接口

```http
POST /api/v5/schedule-repair-tasks
GET  /api/v4/schedule-risks/plans/{planId}
GET  /api/v5/options/repair-modes
GET  /api/v5/options/repair-scope-types
POST /api/v5/schedule-protection/check-locked-impact
```

### 8.6 校验规则

1. 必须选择学期；
2. 必须选择来源类型；
3. 来源为方案时必须选择方案；
4. 单风险修复必须选择至少一个风险；
5. 局部重排必须选择修复范围；
6. 涉及锁定课程时必须弹出影响提示；
7. 创建前必须二次确认。

## 二十七、前端开发禁止事项

V5 前端开发必须禁止：

1. 不允许重写 V3 多方案生成页面；
2. 不允许重写 V3 方案应用和回滚页面；
3. 不允许重写 V4 风险诊断和质量分析页面；
4. 不允许在前端直接修改数据库；
5. 不允许前端直接调用 AI 服务商接口；
6. 不允许把 API Key 写到前端；
7. 不允许只靠前端判断候选位置是否可用；
8. 不允许让修复建议直接修改正式课表；
9. 不允许让候选位置直接写入正式课表；
10. 不允许让局部重排直接覆盖正式课表；
11. 不允许移动锁定课程；
12. 不允许跨学期应用试算方案；
13. 不允许删除历史方案和历史方案明细；
14. 不允许在数据检查页面自动修复高风险数据；
15. 不允许把所有 V5 页面逻辑写到一个大 Vue 文件；
16. 不允许忽略空状态、失败状态和 loading 状态；
17. 不允许把 AI 生成内容当作系统强制决策。

## 二十八、总结

V5 前端的核心不是继续堆普通管理页面，而是把系统从“发现问题”推进到“辅助修复问题”。

V5 前端主线是：

```text
风险诊断
  ↓
修复任务
  ↓
修复建议 / 候选位置
  ↓
试算方案
  ↓
优化前后对比
  ↓
用户确认后应用
```

V5 前端必须始终记住：

```text
修复建议不是正式修改；
候选位置不是正式修改；
试算方案不是正式课表；
只有用户确认应用后，才允许进入正式课表变更流程。
```

只要围绕这条主线开发，V5 就能在 V3 的方案机制和 V4 的分析诊断机制基础上，形成一个更完整、更安全、更适合毕业设计展示的智能修复优化版本。
