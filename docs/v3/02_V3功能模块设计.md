# 02_V3功能模块设计.md

# 排课系统 V3 功能模块设计

## 一、文档说明

本文档用于说明排课系统 V3 版本的功能模块划分、模块职责、模块边界、核心流程和模块之间的数据关系。

V3 版本定位为：

> 智能排课优化与学期方案管理版。

V3 不是推翻 V1/V2 重新开发，而是在现有系统基础上进行增强。V3 的核心是围绕“学期、排课方案、多方案生成、规则权重、评分明细、方案对比、日志解释、版本回滚、统计分析”构建一套更完整的排课优化流程。

本文档主要服务于后续文档：

1. `03_V3数据库设计.md`
2. `04_V3接口设计.md`
3. `05_V3前端页面设计.md`
4. `06_V3自动排课与评分规则设计.md`
5. `07_V3开发阶段任务.md`

后续所有 V3 功能设计都应以本文档的模块划分为基础，避免开发过程中功能发散。

---

## 二、V3 模块设计总原则

### 2.1 不推翻 V1/V2

V3 必须建立在 V1/V2 已有功能之上，不允许重写整个系统。

已有功能如教师管理、班级管理、课程管理、教室管理、教学任务管理、手动排课、自动排课、冲突检测等，应尽量复用和增强。

---

### 2.2 以学期为数据边界

V3 新增“学期”概念。

教学任务、排课方案、课表结果、评分明细、排课日志、统计分析都应归属于某一个学期。

系统应支持当前学期切换，切换后相关业务页面只展示当前学期的数据。

---

### 2.3 以排课方案为核心对象

V3 自动排课不能直接覆盖正式课表。

自动排课生成的结果应先保存为“排课方案”，用户可以查看、评分、对比、调整后，再选择某个方案应用为正式课表。

---

### 2.4 以评分和解释提升系统档次

V3 不只是生成课表，还要说明课表好不好、为什么这样排、哪里存在不足。

因此 V3 必须支持：

1. 评分明细；
2. 未排任务原因；
3. 排课过程日志；
4. 多方案对比；
5. 手动调整后重新评分。

---

### 2.5 控制复杂度

V3 暂时不做真实教务系统级别的复杂功能。

以下内容不属于 V3 主线：

1. 真实教务系统对接；
2. 学生选课；
3. 复杂审批流程；
4. 手机端或小程序；
5. 多学校多租户；
6. 复杂校历与节假日调休；
7. 复杂单双周排课；
8. 强行接入大型约束求解框架；
9. 真实 AI 大模型自动排课。

---

## 三、V3 功能模块总览

V3 建议划分为以下 12 个核心模块：

| 序号 | 模块名称 | 模块定位 |
|---|---|---|
| 1 | 学期管理模块 | 维护学期基础信息，提供当前学期数据边界 |
| 2 | 当前学期切换模块 | 控制系统当前操作学期，影响教学任务、课表和方案 |
| 3 | 教学任务学期化模块 | 将教学任务按学期隔离 |
| 4 | 课表结果学期化模块 | 将正式课表按学期隔离 |
| 5 | 排课方案管理模块 | 管理自动排课生成的候选方案 |
| 6 | 多方案自动排课模块 | 按不同策略生成多个排课方案 |
| 7 | 规则权重配置模块 | 配置硬约束、软约束和评分权重 |
| 8 | 评分明细模块 | 对排课方案进行多维度评分 |
| 9 | 方案对比模块 | 对多个排课方案进行横向对比 |
| 10 | 排课日志模块 | 记录排课过程和关键决策步骤 |
| 11 | 未排任务原因分析模块 | 分析教学任务无法排入课表的原因 |
| 12 | 统计分析模块 | 统计教师工作量、教室利用率、班级均衡度 |

---

## 四、模块一：学期管理模块

### 4.1 模块定位

学期管理模块是 V3 的基础模块，用于维护不同学期的数据范围。

引入学期后，系统可以区分不同时间段的教学任务、排课方案、课表结果和统计结果。

---

### 4.2 核心功能

学期管理模块应支持：

1. 新增学期；
2. 编辑学期；
3. 删除未使用学期；
4. 查看学期列表；
5. 设置当前学期；
6. 修改学期状态；
7. 判断学期是否已经被业务数据引用。

---

### 4.3 学期基础字段

学期建议包含以下信息：

| 字段 | 说明 |
|---|---|
| id | 学期 ID |
| name | 学期名称 |
| school_year | 学年，例如 2025-2026 |
| term | 学期，例如 第一学期、第二学期 |
| start_date | 学期开始日期 |
| end_date | 学期结束日期 |
| is_current | 是否当前学期 |
| status | 学期状态 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

---

### 4.4 学期状态

学期状态建议包括：

1. 未开始；
2. 进行中；
3. 已结束。

状态用于辅助页面展示和业务筛选，不需要设计得过于复杂。

---

### 4.5 业务规则

1. 系统同时只能有一个当前学期；
2. 设置某个学期为当前学期时，其他学期自动取消当前状态；
3. 已被教学任务、排课方案或课表引用的学期，不建议直接删除；
4. 学期名称不建议重复；
5. 学期开始日期不能晚于结束日期。

---

## 五、模块二：当前学期切换模块

### 5.1 模块定位

当前学期切换模块用于控制系统当前操作的数据范围。

用户切换当前学期后，系统内教学任务、排课方案、课表结果、评分统计等页面都应随之切换。

---

### 5.2 展示位置

建议在系统顶部导航栏或首页卡片区域显示当前学期，例如：

```text
当前学期：2025-2026学年第二学期
```

用户可以通过下拉框切换当前学期。

---

### 5.3 影响范围

切换当前学期后，以下页面应按当前学期过滤数据：

1. 教学任务管理；
2. 手动排课；
3. 自动排课；
4. 课表查询；
5. 排课方案管理；
6. 评分明细；
7. 方案对比；
8. 排课日志；
9. 未排任务；
10. 统计分析。

---

### 5.4 业务规则

1. 当前学期是系统级配置，不建议每个页面单独维护；
2. 页面查询时默认携带当前学期 ID；
3. 自动排课时只能读取当前学期的教学任务；
4. 应用排课方案时只能应用到对应学期的正式课表；
5. 不同学期之间的数据不得混用。

---

## 六、模块三：教学任务学期化模块

### 6.1 模块定位

教学任务学期化模块用于将原有教学任务绑定到具体学期。

V3 中，教学任务不再是全局数据，而是某个学期内需要完成的排课任务。

---

### 6.2 核心功能

该模块需要支持：

1. 新增教学任务时选择学期；
2. 默认使用当前学期创建教学任务；
3. 教学任务列表按当前学期筛选；
4. 自动排课只读取当前学期的教学任务；
5. 不同学期可以存在相同课程、班级、教师组合的教学任务；
6. 支持后续从历史学期复制教学任务到新学期，但该功能可作为后续选做。

---

### 6.3 改造重点

原有教学任务表建议增加：

```text
semester_id
```

所有教学任务查询、统计、排课逻辑，都应考虑 `semester_id`。

---

### 6.4 业务规则

1. 教学任务必须归属于一个学期；
2. 未绑定学期的历史教学任务需要迁移到默认学期；
3. 删除学期前必须检查该学期是否存在教学任务；
4. 自动排课不能跨学期读取教学任务；
5. 教学任务的排课状态应按学期独立计算。

---

## 七、模块四：课表结果学期化模块

### 7.1 模块定位

课表结果学期化模块用于将正式课表绑定到具体学期。

这样可以保留不同学期的历史课表，避免 V3 多方案排课影响旧数据。

---

### 7.2 核心功能

该模块应支持：

1. 当前学期课表查询；
2. 历史学期课表查询；
3. 按教师查看某学期课表；
4. 按班级查看某学期课表；
5. 按教室查看某学期课表；
6. 将某个排课方案应用为当前学期正式课表；
7. 回滚到历史排课方案。

---

### 7.3 改造重点

原有课表结果表建议增加：

```text
semester_id
```

若系统原本使用 `schedule` 表保存正式课表，则 V3 应保证每条课表记录都能追溯到具体学期。

---

### 7.4 业务规则

1. 正式课表必须归属于某个学期；
2. 应用方案时，只能覆盖该方案所属学期的正式课表；
3. 不同学期的正式课表互不影响；
4. 查询课表时默认按当前学期展示；
5. 历史课表应允许查看，但不建议随意修改。

---

## 八、模块五：排课方案管理模块

### 8.1 模块定位

排课方案管理模块是 V3 的核心模块。

V3 中，自动排课不再直接生成正式课表，而是先生成排课方案。用户可以查看方案、评分、对比、微调，确认后再应用为正式课表。

---

### 8.2 方案状态

排课方案建议包含以下状态：

1. 草稿；
2. 已应用；
3. 已废弃。

状态说明：

| 状态 | 说明 |
|---|---|
| 草稿 | 自动排课生成但尚未应用 |
| 已应用 | 已经应用为正式课表 |
| 已废弃 | 用户不再使用的方案 |

---

### 8.3 核心功能

排课方案管理应支持：

1. 生成排课方案；
2. 查看方案列表；
3. 查看方案详情；
4. 查看方案课表；
5. 查看方案评分；
6. 查看方案未排任务；
7. 应用方案为正式课表；
8. 废弃方案；
9. 删除草稿方案；
10. 回滚到历史方案。

---

### 8.4 方案信息

排课方案建议包含：

| 字段 | 说明 |
|---|---|
| id | 方案 ID |
| semester_id | 所属学期 |
| name | 方案名称 |
| strategy_type | 生成策略 |
| status | 方案状态 |
| total_score | 总评分 |
| scheduled_count | 已排任务数 |
| unscheduled_count | 未排任务数 |
| conflict_count | 冲突数量 |
| created_at | 创建时间 |
| applied_at | 应用时间 |

---

### 8.5 业务规则

1. 排课方案必须绑定学期；
2. 生成方案不允许直接覆盖正式课表；
3. 一个学期可以有多个排课方案；
4. 一个学期最多只有一个当前已应用方案；
5. 应用新方案时，应将旧的已应用方案保留为历史记录；
6. 已应用方案不建议直接删除；
7. 方案详情中的课表明细应与正式课表分开保存。

---

## 九、模块六：多方案自动排课模块

### 9.1 模块定位

多方案自动排课模块用于根据不同策略生成多个排课候选方案。

V2 如果已经有自动排课能力，V3 应在 V2 的基础上扩展为“多策略、多方案、可评分”的自动排课。

---

### 9.2 方案策略

V3 建议支持以下几类方案：

| 方案类型 | 说明 |
|---|---|
| 教师优先方案 | 优先满足教师禁排时间和教师课程分布 |
| 班级均衡方案 | 优先让班级每天课程分布更均匀 |
| 教室利用率方案 | 优先提升教室使用效率 |
| 综合最优方案 | 综合考虑教师、班级、教室和课程分布 |

---

### 9.3 核心功能

该模块应支持：

1. 选择当前学期；
2. 选择生成策略；
3. 一次生成单个方案；
4. 一次生成多个方案；
5. 生成过程中进行冲突检测；
6. 对每个方案计算评分；
7. 记录排课日志；
8. 记录未排任务原因；
9. 保存方案明细；
10. 返回生成结果。

---

### 9.4 业务规则

1. 自动排课只读取当前学期的教学任务；
2. 自动排课生成的是排课方案，不是正式课表；
3. 不同策略可以使用不同权重；
4. 所有方案生成完成后必须计算评分；
5. 对无法排课的任务必须给出原因；
6. 方案生成失败时不能影响已有正式课表；
7. 生成过程应有日志记录。

---

## 十、模块七：规则权重配置模块

### 10.1 模块定位

规则权重配置模块用于管理排课评分与方案生成时使用的规则权重。

V3 中，规则不再只是固定判断，而是可以通过权重影响不同方案的生成结果和评分结果。

---

### 10.2 规则类型

规则分为两类：

#### 10.2.1 硬约束

硬约束是必须满足的规则。

例如：

1. 同一教师同一时间不能上多门课；
2. 同一班级同一时间不能上多门课；
3. 同一教室同一时间不能安排多门课；
4. 教师禁排时间不能安排课程；
5. 教室容量必须满足班级人数；
6. 课程类型应匹配教室类型。

#### 10.2.2 软约束

软约束是尽量满足的规则。

例如：

1. 教师每天课程不要过多；
2. 班级每天课程不要过满；
3. 同一课程不要过度集中；
4. 课程分布尽量均匀；
5. 理论课优先安排在上午；
6. 实验课优先安排实验室；
7. 体育课避免安排在晚上。

---

### 10.3 核心功能

规则权重配置模块应支持：

1. 查看规则列表；
2. 设置规则是否启用；
3. 设置规则权重；
4. 区分硬约束和软约束；
5. 按方案策略加载不同默认权重；
6. 恢复默认权重；
7. 保存当前权重配置。

---

### 10.4 业务规则

1. 硬约束不建议关闭；
2. 软约束可以调整权重；
3. 不同方案策略可以使用不同权重组合；
4. 权重用于影响评分和候选位置选择；
5. 权重配置变更后，不应自动修改历史方案评分，除非用户主动重新评分。

---

## 十一、模块八：评分明细模块

### 11.1 模块定位

评分明细模块用于对排课方案进行多维度评价。

V3 不能只显示一个总分，还应显示每个评分项的得分或扣分原因。

---

### 11.2 评分维度

评分维度建议包括：

1. 教师冲突；
2. 班级冲突；
3. 教室冲突；
4. 教师禁排违规；
5. 教室容量匹配；
6. 课程教室类型匹配；
7. 班级课程分布均衡度；
8. 教师工作量均衡度；
9. 教室利用率；
10. 连续上课情况；
11. 未排任务数量。

---

### 11.3 核心功能

评分明细模块应支持：

1. 自动计算方案总分；
2. 生成评分明细；
3. 显示每个评分项得分；
4. 显示扣分原因；
5. 支持手动调整后重新评分；
6. 支持方案对比时读取评分明细；
7. 支持历史方案评分查看。

---

### 11.4 业务规则

1. 每个排课方案都应有评分结果；
2. 评分结果应保存为历史记录；
3. 手动调整方案后应重新评分；
4. 评分不能只保存在前端，应由后端计算或确认；
5. 总分建议采用 100 分制；
6. 硬约束违规应严重扣分或直接标记为不可用方案。

---

## 十二、模块九：方案对比模块

### 12.1 模块定位

方案对比模块用于对多个排课方案进行横向比较，帮助用户选择更优方案。

---

### 12.2 对比维度

方案对比建议包含：

| 对比项 | 说明 |
|---|---|
| 总分 | 方案整体评分 |
| 已排任务数 | 成功安排的教学任务数量 |
| 未排任务数 | 未能安排的教学任务数量 |
| 教师冲突数 | 教师时间冲突数量 |
| 班级冲突数 | 班级时间冲突数量 |
| 教室冲突数 | 教室占用冲突数量 |
| 禁排违规数 | 教师禁排时间违规数量 |
| 教室利用率 | 教室资源使用情况 |
| 班级均衡度 | 班级每天课程分布情况 |
| 教师工作量均衡度 | 教师课程分布情况 |

---

### 12.3 核心功能

方案对比模块应支持：

1. 选择两个或多个方案；
2. 以表格形式展示对比结果；
3. 高亮最优方案；
4. 查看某个方案详情；
5. 查看方案评分明细；
6. 查看方案未排任务；
7. 从对比页面应用方案。

---

### 12.4 业务规则

1. 只能对比同一学期下的方案；
2. 不同学期方案不允许直接对比；
3. 对比结果应基于方案生成时保存的数据；
4. 如果方案被手动调整，应使用最新评分结果参与对比；
5. 已废弃方案可以查看，但默认不参与对比。

---

## 十三、模块十：排课日志模块

### 13.1 模块定位

排课日志模块用于记录自动排课过程中的关键步骤和决策信息。

它是 V3 的重要展示亮点，可以让系统具备“可解释性”。

---

### 13.2 日志类型

排课日志建议分为两类：

1. 方案级日志；
2. 任务级日志。

方案级日志记录整个方案生成过程。

任务级日志记录单个教学任务排课时的筛选、判断和结果。

---

### 13.3 日志内容示例

```text
开始生成排课方案
读取当前学期教学任务
检测教师可用时间
检测班级可用时间
检测教室可用时间
生成候选时间段
计算候选位置评分
选择最优时间与教室
保存排课方案明细
计算方案评分
生成未排任务原因
排课方案生成完成
```

---

### 13.4 核心功能

排课日志模块应支持：

1. 查看方案生成日志；
2. 查看单个教学任务排课日志；
3. 按日志级别筛选；
4. 按教学任务筛选；
5. 按时间倒序展示；
6. 查看失败原因；
7. 支持调试自动排课过程。

---

### 13.5 业务规则

1. 日志应绑定排课方案；
2. 日志应绑定学期；
3. 自动排课过程中的关键步骤都应记录；
4. 日志不应影响正常排课性能；
5. 日志主要用于展示、调试和答辩说明，不需要做复杂审计系统。

---

## 十四、模块十一：未排任务原因分析模块

### 14.1 模块定位

未排任务原因分析模块用于解释某些教学任务为什么没有成功排入课表。

V3 不应只显示“未排”，而应显示具体原因。

---

### 14.2 常见未排原因

未排原因建议包括：

1. 教师无可用时间；
2. 班级无可用时间；
3. 教室无可用时间；
4. 教室容量不足；
5. 缺少指定类型教室；
6. 教师禁排时间冲突；
7. 课程周课时过多；
8. 可用节次不足；
9. 硬约束冲突无法解决；
10. 系统规则配置过于严格。

---

### 14.3 核心功能

该模块应支持：

1. 查看某个方案下的未排任务；
2. 查看未排原因；
3. 查看相关冲突信息；
4. 支持按原因类型筛选；
5. 支持从未排任务跳转到教学任务详情；
6. 支持重新尝试排课或手动调整。

---

### 14.4 业务规则

1. 每条未排任务都应绑定具体方案；
2. 每条未排任务应有原因类型；
3. 原因说明应尽量清楚，便于用户理解；
4. 未排任务不应直接从教学任务中删除；
5. 未排任务应参与方案评分和方案对比。

---

## 十五、模块十二：统计分析模块

### 15.1 模块定位

统计分析模块用于对当前学期的排课结果进行数据分析，提升系统展示效果和答辩说服力。

---

### 15.2 教师工作量统计

统计内容包括：

1. 教师总课时；
2. 每周课时；
3. 每天课程数量；
4. 连续上课节数；
5. 教师课时排名。

---

### 15.3 教室利用率统计

统计内容包括：

1. 教室使用次数；
2. 教室空闲次数；
3. 教室利用率；
4. 最常用教室；
5. 长期空闲教室。

---

### 15.4 班级课表均衡度统计

统计内容包括：

1. 班级每天课程数量；
2. 上午课程数量；
3. 下午课程数量；
4. 晚上课程数量；
5. 是否存在某天课程过多；
6. 是否存在某天课程过少。

---

### 15.5 核心功能

统计分析模块应支持：

1. 按当前学期统计；
2. 按教师统计；
3. 按教室统计；
4. 按班级统计；
5. 查看图表或表格；
6. 支持从统计结果跳转到课表详情。

---

### 15.6 业务规则

1. 统计分析默认基于当前学期正式课表；
2. 也可以查看某个排课方案的统计结果；
3. 统计结果应与课表数据一致；
4. 统计数据可以实时计算，也可以在方案生成后保存汇总结果；
5. V3 中统计展示以表格和简单图表为主，不追求复杂大屏。

---

## 十六、V3 主要业务流程

### 16.1 学期初始化流程

```text
新增学期
设置为当前学期
系统顶部显示当前学期
教学任务默认归属当前学期
后续排课操作全部基于当前学期
```

---

### 16.2 多方案自动排课流程

```text
选择当前学期
读取当前学期教学任务
读取教师、班级、课程、教室等基础数据
读取规则权重配置
选择生成策略
执行自动排课
生成排课方案
保存方案明细
计算评分明细
生成排课日志
生成未排任务原因
展示方案结果
```

---

### 16.3 方案应用流程

```text
查看方案列表
选择一个方案
查看方案课表
查看评分明细
查看未排任务
确认应用方案
清理当前学期原正式课表或标记旧方案
将方案明细写入正式课表
更新方案状态为已应用
保留历史方案记录
```

---

### 16.4 手动调整并重新评分流程

```text
进入方案详情
手动调整某节课时间或教室
系统执行冲突检测
保存调整记录
重新计算方案评分
更新评分明细
更新方案对比数据
```

---

### 16.5 方案对比流程

```text
选择同一学期下多个排课方案
读取各方案评分结果
读取已排任务和未排任务统计
读取冲突数量
读取教师、班级、教室统计数据
生成对比表格
高亮推荐方案
用户选择应用某个方案
```

## 十八、模块依赖关系

V3 各模块之间的依赖关系如下：

```text
学期管理
  ↓
当前学期切换
  ↓
教学任务学期化
  ↓
多方案自动排课
  ↓
排课方案管理
  ↓
评分明细 / 未排原因 / 排课日志
  ↓
方案对比
  ↓
应用为正式课表
  ↓
统计分析
```

核心依赖说明：

1. 没有学期管理，就无法实现数据隔离；
2. 没有教学任务学期化，就无法按学期排课；
3. 没有排课方案，就无法实现多方案对比和版本回滚；
4. 没有评分明细，就无法判断方案优劣；
5. 没有日志和未排原因，就无法解释排课过程；
6. 没有统计分析，V3 的展示效果会变弱。

## 二十二、V3 模块验收标准

V3 功能模块整体完成后，应满足以下标准：

1. 系统可以创建和切换学期；
2. 教学任务可以按学期隔离；
3. 正式课表可以按学期隔离；
4. 自动排课生成的是排课方案，不直接覆盖正式课表；
5. 同一学期可以生成多个排课方案；
6. 每个方案都有方案明细；
7. 每个方案都有评分结果；
8. 每个方案可以查看未排任务原因；
9. 每个方案可以查看排课日志；
10. 多个方案可以进行对比；
11. 用户可以选择某个方案应用为正式课表；
12. 用户可以查看当前学期正式课表；
13. 用户可以查看教师、教室、班级相关统计；
14. V1/V2 原有功能不被破坏；
15. 系统能够支撑毕业设计演示和答辩说明。

## 二十四、总结

V3 的核心不是继续增加普通管理页面，而是让排课系统具备“学期化、方案化、可评分、可对比、可解释、可回滚”的能力。

V3 最重要的设计主线是：

> 以学期为数据边界，以排课方案为核心对象，以多方案生成、评分明细、方案对比、日志解释和统计分析作为主要亮点。

只要围绕这条主线开发，V3 就能在 V1/V2 的基础上明显提升系统完整度、技术含量和答辩展示效果。
