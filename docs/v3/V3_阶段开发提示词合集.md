# 排课系统 V3 阶段开发提示词合集

## 一、使用说明

本文档是从 `09_V3_AI开发规则与提示词.md` 中单独提取出来的提示词版本。

用途：

```text
1. 直接复制给 AI 编程助手使用；
2. 按阶段推进 V3 开发；
3. 避免一次性让 AI 做太多导致项目失控；
4. 约束 AI 不要破坏 V1/V2；
5. 让 AI 每个阶段完成后输出修改文件和测试步骤。
```

适用工具：

```text
Claude Code
Trae
CodeBuddy
Codex CLI
Cursor
其他 AI 编程助手
```

V3 版本名称：

```text
智能排课优化与学期方案管理版
```

V3 开发主线：

```text
以学期为数据边界
以排课方案为核心对象
以多方案生成、评分明细、方案对比、日志解释、未排原因和版本回滚为主要亮点
```

本次任务：
【在这里填写当前任务】

# 八、阶段 5 提示词：多方案自动排课

```text
现在开始开发 V3 阶段 5：多方案自动排课。

请实现 V3 的核心功能：生成单个排课方案和一次生成多个排课方案。

本阶段目标：
1. 实现 POST /api/v3/schedule-generate；
2. 实现 POST /api/v3/schedule-generate/multiple；
3. 自动排课结果写入 schedule_plan 和 schedule_plan_item；
4. 根据规则权重计算方案评分；
5. 更新方案 total_score、scheduled_count、unscheduled_count、conflict_count；
6. 前端实现多方案生成页面；
7. 生成后可以跳转方案详情。

算法要求：
1. 使用贪心算法 + 候选评分；
2. 先排更难排的教学任务；
3. 候选位置必须检测教师冲突、班级冲突、教室冲突；
4. 必须考虑教师禁排时间；
5. 必须考虑教室容量；
6. 必须考虑教室类型；
7. 不同策略使用不同规则权重；
8. 无法安排的任务记录未排数量，原因分析可以后续完善。

重要限制：
1. 自动排课绝对不能直接覆盖正式课表；
2. 自动排课只能生成方案；
3. 不要删除历史方案；
4. 所有方案必须绑定当前学期；
5. 不要引入复杂求解器；
6. 不要重写整个 V2 自动排课模块。

完成后请给出：
1. 自动排课流程说明；
2. 生成单方案测试步骤；
3. 生成多方案测试步骤；
4. 如何确认正式课表没有被覆盖；
5. 本阶段修改文件清单。
```
