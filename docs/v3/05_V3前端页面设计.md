# 排课系统 V3 前端页面设计

## 一、文档说明

本文档用于说明排课系统 V3 版本的前端页面设计方案。

V3 版本的前端重点不再只是普通增删改查页面，而是围绕以下能力进行页面升级：

1. 学期管理；
2. 当前学期切换；
3. 教学任务按学期隔离；
4. 正式课表按学期查看；
5. 排课方案管理；
6. 多方案自动排课；
7. 规则权重配置；
8. 评分明细展示；
9. 方案对比；
10. 排课过程日志；
11. 未排任务原因分析；
12. 手动微调后重新评分；
13. 教师工作量统计；
14. 教室利用率统计；
15. 班级课表均衡度分析；
16. 答辩演示数据与展示优化。

本文档需要与以下文档保持一致：

```text
01_V3版本需求说明.md
02_V3功能模块设计.md
03_V3数据库设计.md
04_V3接口设计.md
```

---

## 二、V3 前端设计目标

V3 前端的目标不是单纯增加页面数量，而是让系统看起来像一个完整的“排课方案决策系统”。

V3 前端需要体现：

```text
按学期管理数据
自动生成多个排课方案
可以查看方案质量
可以对比不同方案
可以解释排课过程
可以查看未排原因
可以手动微调并重新评分
可以统计教师、教室、班级维度的数据
```

最终效果应该是：

> 用户进入系统后，可以先选择当前学期，再生成多个排课方案，然后查看每个方案的课表、评分、日志、未排原因，并选择最合适的方案应用为正式课表。

---

## 三、前端整体页面结构建议

V3 建议在原有 V1/V2 菜单基础上新增一个大的菜单分组：

```text
V3 排课优化
```

菜单结构建议如下：

```text
首页 / 控制台
基础数据管理
教学任务管理
课表管理
自动排课
V3 排课优化
  ├── 学期管理
  ├── 排课方案管理
  ├── 多方案生成
  ├── 规则权重配置
  ├── 方案对比
  ├── 排课日志
  ├── 未排任务分析
  └── 统计分析
系统设置
```

如果项目左侧菜单不想太复杂，也可以合并成：

```text
V3 排课优化
  ├── 学期与方案
  ├── 方案生成
  ├── 方案对比
  ├── 日志与未排
  └── 统计分析
```

但从开发清晰度看，建议先按页面拆细。

## 四、顶部当前学期切换设计

## 4.1 页面位置

建议在系统顶部导航栏右侧增加当前学期显示和切换入口。

示例：

```text
当前学期：2025-2026学年第二学期  [切换]
```

或者：

```text
学期：[2025-2026学年第二学期 ▼]
```

---

## 4.2 功能说明

用户切换当前学期后，以下页面数据需要随之刷新：

```text
教学任务列表
课表查询
排课方案列表
多方案生成
评分明细
方案对比
排课日志
未排任务
统计分析
```

---

## 4.3 交互规则

1. 页面加载时，调用当前学期接口；
2. 如果没有当前学期，提示用户先创建学期；
3. 切换学期后，前端保存当前学期 ID；
4. 后续 V3 相关接口默认携带 semesterId；
5. 切换学期后，当前页面应重新请求数据；
6. 如果当前页面存在未保存内容，切换前需要提示。

---

## 4.4 推荐接口

```text
GET /api/v3/semesters/current
GET /api/v3/semesters
PUT /api/v3/semesters/{id}/current
```

## 五、页面一：学期管理页面

## 5.1 页面路径建议

```text
/v3/semesters
```

---

## 5.2 页面作用

用于管理系统中的学年学期，并设置当前学期。

V3 中所有核心数据都需要绑定学期，因此该页面是 V3 的基础页面。

---

## 5.3 页面主要区域

### 5.3.1 顶部操作区

包含：

```text
新增学期
刷新
搜索框
状态筛选
```

筛选条件：

```text
学期名称
学年
学期状态
是否当前学期
```

---

### 5.3.2 学期列表表格

表格字段建议：

| 字段 | 说明 |
|---|---|
| 学期名称 | 例如 2025-2026学年第二学期 |
| 学年 | 例如 2025-2026 |
| 学期 | 第一学期 / 第二学期 |
| 开始日期 | 学期开始日期 |
| 结束日期 | 学期结束日期 |
| 当前学期 | 是 / 否 |
| 状态 | 未开始 / 进行中 / 已结束 |
| 备注 | 简短说明 |
| 操作 | 编辑、设为当前、删除 |

---

### 5.3.3 新增 / 编辑弹窗

表单字段：

```text
学期名称
学年
学期
开始日期
结束日期
状态
备注
```

校验要求：

```text
学期名称必填
学年必填
学期必填
结束日期不能早于开始日期
```

---

### 5.3.4 设置当前学期确认弹窗

用户点击“设为当前”时，需要二次确认：

```text
确定将“2025-2026学年第二学期”设置为当前学期吗？
切换后，教学任务、课表、排课方案和统计数据将按该学期展示。
```

---

## 5.4 页面状态提示

如果没有任何学期，显示空状态：

```text
暂无学期数据，请先新增一个学期。
```

如果没有当前学期，显示警告：

```text
当前未设置学期，部分排课功能无法使用。
```

如果需要查看历史学期任务，可以提供学期下拉框。

## 八、页面四：排课方案管理页面

## 8.1 页面路径建议

```text
/v3/schedule-plans
```

---

## 8.2 页面作用

用于查看当前学期下的所有排课方案，包括草稿方案、已应用方案和已废弃方案。

这是 V3 的核心页面之一。

---

## 8.3 页面主要区域

### 8.3.1 顶部操作区

包含：

```text
生成单个方案
生成多个方案
刷新
方案状态筛选
方案策略筛选
关键词搜索
```

---

### 8.3.2 方案列表表格

表格字段建议：

| 字段 | 说明 |
|---|---|
| 方案名称 | 例如 综合最优方案-001 |
| 所属学期 | 当前方案所属学期 |
| 策略类型 | 教师优先 / 班级均衡 / 教室利用率 / 综合最优 |
| 状态 | 草稿 / 已应用 / 已废弃 |
| 总分 | 方案评分 |
| 已排数量 | 已成功安排任务数 |
| 未排数量 | 未安排任务数 |
| 冲突数量 | 冲突数 |
| 生成时间 | 自动排课生成时间 |
| 应用时间 | 应用为正式课表的时间 |
| 操作 | 详情、对比、应用、废弃、删除 |

---

## 8.4 状态标签颜色建议

```text
草稿：蓝色
已应用：绿色
已废弃：灰色
存在冲突：红色
有未排任务：橙色
```

---

## 8.5 操作按钮规则

| 状态 | 可用操作 |
|---|---|
| 草稿 | 详情、应用、对比、废弃、删除 |
| 已应用 | 详情、对比、回滚、废弃 |
| 已废弃 | 详情、对比、删除或保留 |

---

## 8.6 应用方案确认弹窗

点击“应用方案”时，必须弹出确认：

```text
确定将该方案应用为当前学期正式课表吗？
应用后，当前学期正式课表将以该方案为准。
```

如果方案存在未排任务，需要提示：

```text
该方案存在 2 个未排任务，是否仍然应用？
```

如果方案存在冲突，需要强提示：

```text
该方案存在冲突，不建议应用。请先查看冲突详情。
```

## 二十三、V3 前端验收标准

V3 前端开发完成后，应满足以下要求：

```text
1. 顶部可以显示当前学期；
2. 可以切换当前学期；
3. 可以新增、编辑、删除学期；
4. 教学任务页面可以按学期隔离；
5. 课表页面可以按学期隔离；
6. 可以生成单个排课方案；
7. 可以一次生成多个排课方案；
8. 可以查看排课方案列表；
9. 可以查看排课方案详情；
10. 可以查看方案课表明细；
11. 可以查看方案评分明细；
12. 可以查看未排任务原因；
13. 可以查看排课生成日志；
14. 可以手动调整方案中的课程安排；
15. 手动调整后可以显示评分变化；
16. 可以对比多个排课方案；
17. 可以应用某个方案为正式课表；
18. 可以查看教师工作量统计；
19. 可以查看教室利用率统计；
20. 可以查看班级课表均衡度统计；
21. 页面切换学期后数据不会混乱；
22. V1/V2 原有页面不被破坏。
```

## 二十四、不要在 V3 前端中做的内容

V3 前端不要加入以下内容：

```text

移动端小程序页面
支付页面
真实教务系统对接页面
多学校多租户后台
复杂校历节假日调休页面
过度复杂的大屏可视化
```

V3 的重点是：

```text
学期
方案
评分
对比
日志
统计
```

不要偏离主线。

# 结语

V3 前端设计的核心是：

```text
用学期切换控制数据边界
用排课方案承载自动排课结果
用评分明细说明方案质量
用方案对比辅助用户决策
用排课日志解释生成过程
用统计分析增强答辩展示效果
```

前端开发时必须记住：

```text
自动排课结果不是正式课表
方案应用后才成为正式课表
所有核心页面都必须围绕当前学期展示数据
```
