# 排课系统 V3 测试与验收清单

## 一、文档说明

本文档用于排课系统 V3 版本的测试与验收。

V3 版本名称：

```text
智能排课优化与学期方案管理版
```

V3 主要新增能力包括：

```text
学期管理
当前学期切换
教学任务按学期隔离
正式课表按学期隔离
排课方案管理
多方案自动排课
规则权重配置
评分明细
方案对比
排课日志
未排任务原因分析
手动调整后重新评分
统计分析
方案应用与回滚
```

本文档用于：

1. 每个开发阶段结束后的自测；
2. AI 辅助开发后的验收；
3. 前后端联调检查；
4. 最终答辩前完整验收；
5. 防止 V3 功能开发完成但无法跑通业务闭环。

---

## 二、测试总原则

## 2.1 先保证 V1/V2 不被破坏

V3 是在 V1/V2 基础上升级，不允许因为 V3 新功能导致旧功能不能使用。

每次完成 V3 阶段后，都要检查：

```text
教师管理是否正常
班级管理是否正常
课程管理是否正常
教室管理是否正常
教学任务管理是否正常
手动排课是否正常
课表查询是否正常
V2 自动排课是否正常或至少不报错
冲突检测是否正常
Excel 导入导出是否正常
```

如果 V1/V2 功能被破坏，必须优先修复。

---

## 2.2 每个阶段都要启动前后端测试

每个阶段完成后都要确认：

```text
后端能正常启动
前端能正常启动
浏览器页面能正常访问
控制台无明显报错
接口请求无明显 500 错误
数据库数据没有异常丢失
```

---

## 2.3 所有 V3 核心数据必须按学期隔离

V3 最重要的数据边界是学期。

测试时必须确认：

```text
切换学期后，教学任务列表变化
切换学期后，课表数据变化
切换学期后，排课方案列表变化
切换学期后，统计数据变化
不同学期的数据不会混在一起
```

---

## 2.4 自动排课不得直接覆盖正式课表

V3 自动排课只能生成排课方案。

正确流程：

```text
生成方案
查看方案
对比方案
应用方案
正式课表更新
```

错误流程：

```text
点击自动排课后直接覆盖正式课表
生成方案时删除旧正式课表
生成草稿方案时影响已应用课表
```

测试时必须重点检查。

---

## 2.5 测试必须覆盖正常流程和异常流程

不能只测“成功情况”。

还要测：

```text
没有当前学期
当前学期没有教学任务
没有可用教室
教师时间冲突
班级时间冲突
教室时间冲突
方案已废弃
方案存在未排任务
方案存在冲突
重复设置当前学期
删除已使用学期
```

# 二十、常见问题排查

## 20.1 切换学期后数据没变化

可能原因：

```text
前端没有传 semesterId
后端没有按 semesterId 过滤
当前学期状态没有更新成功
前端缓存了旧数据
```

排查：

```text
检查请求参数
检查接口返回
检查数据库 semester_id
刷新页面重新测试
```

---

## 20.2 自动排课直接改变了正式课表

这是严重问题。

应检查：

```text
自动排课接口是否写入 schedule 表
是否误用了 V2 自动排课逻辑
是否没有区分 schedule_plan_item 和 schedule
```

正确做法：

```text
生成方案只写 schedule_plan 和 schedule_plan_item
应用方案才写 schedule
```

---

## 20.3 方案评分为 0 或为空

可能原因：

```text
规则权重未初始化
评分逻辑未执行
评分明细未写入
方案明细为空
```

排查：

```text
检查 schedule_rule_weight
检查 schedule_plan_item
检查 schedule_score_detail
检查 rescore 接口
```

---

## 20.4 未排任务没有原因

可能原因：

```text
未实现原因分析
只记录了未排数量
没有写入 schedule_unassigned_task
reason_code 为空
```

正确要求：

```text
每个未排任务必须有 reason_code、reason_message、suggestion
```

---

## 20.5 应用方案后课表为空

可能原因：

```text
方案明细为空
应用方案时没有复制 schedule_plan_item
schedule.semester_id 未写入
正式课表查询学期不一致
```

排查：

```text
检查方案明细
检查 schedule 表
检查 semester_id
检查课表查询接口参数
```

---

# 结语

V3 测试验收的核心是：

```text
先保证旧功能不坏
再验证学期隔离
再验证方案生成
再验证评分对比
再验证应用回滚
最后验证日志、未排和统计
```

只要以下流程能完整跑通，V3 就基本达标：

```text
创建学期 -> 创建教学任务 -> 初始化规则 -> 生成多个方案 -> 查看评分日志 -> 对比方案 -> 应用方案 -> 查看正式课表 -> 查看统计分析
```

V3 最关键的红线是：

```text
自动排课不能直接覆盖正式课表
不同学期数据不能混在一起
V1/V2 原有功能不能被破坏
```
