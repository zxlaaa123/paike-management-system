# V4_00_开发前检查记录

## 目的

基于 `V4_06_开发阶段计划.md` 的阶段 0 要求，先确认当前项目的 `V3` 数据结构、接口与页面是否具备承接 `V4` 的基础条件。

## 当前结论

当前仓库已经具备进入 `V4` 开发的基础，建议按文档顺序从 `阶段 0 -> 阶段 1` 推进。

## V3 数据结构检查

已确认以下核心对象存在：

- `semester`
- `teaching_task`
- `schedule`
- `schedule_plan`
- `schedule_plan_item`
- `schedule_rule_weight`
- `schedule_score_detail`
- `schedule_generate_log`
- `schedule_unassigned_task`
- `schedule_adjust_log`

当前可直接承接 `V4` 的关键点：

- `schedule_plan` 可作为 `V4` 分析主对象；
- `schedule_plan_item` 可作为质量分析、风险诊断、图表统计的数据来源；
- `schedule.plan_id` 已存在，可追踪正式课表来源方案；
- `semester_id` 已贯通 `V3` 核心数据，可继续作为 `V4` 数据边界。

当前未额外补充的点：

- `schedule.source_plan_id` 未单独新增，因为现有 `schedule.plan_id` 已能满足来源方案追踪；
- `source_plan_item_id` 暂未新增，后续如果 `V4` 阶段 5/6 需要更细粒度来源追踪，再最小增量补充。

## V3 接口检查

已确认以下 `V3` 接口在代码中存在：

- `GET /api/v3/schedule-plans`
- `GET /api/v3/schedule-plans/{id}`
- `GET /api/v3/schedule-plans/{planId}/items`
- `POST /api/v3/schedule-plans/compare`
- `POST /api/v3/schedule-plans/{id}/apply`
- `POST /api/v3/schedule-plans/{id}/rollback`
- `GET /api/v3/schedule-plans/{planId}/logs`
- `GET /api/v3/schedule-plans/{planId}/unassigned-tasks`
- `GET /api/v3/schedule-plans/{planId}/unassigned-summary`
- `GET /api/v3/schedule-plans/{planId}/score-details`
- `GET /api/v3/schedule-plans/{planId}/score-summary`
- `POST /api/v3/schedule-plans/{planId}/rescore`
- `GET /api/v3/schedule-adjust-logs`

结论：

- `V4` 阶段 1-4 的只读分析能力可以直接复用现有 `V3` 数据与接口；
- `V4` 不需要重写 `V3` 的生成、应用、回滚链路；
- `V4` 分析页面应以新增路由和新增只读接口为主。

## V3 页面检查

已确认以下页面存在且可作为 `V4` 入口挂载点：

- `frontend/src/views/schedule/SchedulePlanView.vue`
- `frontend/src/views/schedule/SchedulePlanDetailView.vue`
- `frontend/src/views/schedule/ScheduleCompareView.vue`
- `frontend/src/views/schedule/ScheduleStatisticsView.vue`
- `frontend/src/views/schedule/ScheduleView.vue`

结论：

- `V4` 可以在 `V3` 方案列表、方案详情中增加“进入分析”入口；
- 不需要重写 `V3` 页面主体；
- 正式课表来源增强可放到后续 `V4` 阶段 5 再做。

## 本阶段已做的准备

- 新增 `frontend/src/views/v4/` 页面骨架；
- 新增 `V4` 路由占位；
- 在侧边菜单和 `V3` 方案页增加 `V4` 分析入口；
- 保持所有 `V4` 分析入口为只读导航，不写数据库。

## 风险与约束

- 当前 `V4` 页面入口已预留，但阶段 1 的正式分析接口尚未落地；
- 旧方案若缺少更细的来源字段，后续明细级追踪功能需要再补；
- 后续所有 `V4` 分析、评分、图表接口必须保持只读；
- 任何正式课表写操作仍然必须通过既有 `V3 apply/rollback` 或后续明确的写接口。
