# V4 版本前端页面设计

## 一、文档说明

本文档用于指导“排课系统仿真”V4 版本前端页面开发。

V4 版本定位为：

> 排课质量分析与智能辅助优化版。

V4 前端页面的重点不是重新设计基础管理页面，也不是替代 V3 的多方案生成、方案详情、方案对比、应用和回滚页面，而是在 V3 已有排课方案数据基础上，增加：

1. 排课质量分析；
2. 评分详情解释；
3. 冲突风险诊断；
4. 可视化图表展示；
5. 局部调整与冲突检测；
6. 课程锁定；
7. 局部重排入口；
8. 报告生成与导出；
9. AI 辅助分析建议。

---

## 二、前端设计原则

### 2.1 不推翻 V3 页面

V3 已经存在或规划的页面包括：

1. 多方案生成页面；
2. 方案列表页面；
3. 方案详情页面；
4. 方案对比页面；
5. 正式课表页面；
6. 应用方案与回滚操作入口。

V4 不应重写这些页面，而是在这些页面基础上增加分析入口和辅助功能。

推荐方式：

```text
V3 页面负责方案查看、对比、应用、回滚；
V4 页面负责分析、解释、诊断、可视化、辅助调整和报告。
```

---

### 2.2 分析页面默认只读

以下页面默认只读：

1. 排课质量分析总览页；
2. 评分详情页；
3. 冲突风险诊断页；
4. 可视化图表页；
5. 报告预览页；
6. AI 分析建议页。

这些页面不能直接修改正式课表。

---

### 2.3 修改类操作必须有确认

以下操作必须有确认弹窗：

1. 局部调整课程；
2. 强制保存有冲突的调整；
3. 锁定课程；
4. 取消课程锁定；
5. 创建局部重排方案；
6. 生成报告；
7. 应用局部重排后的新方案；
8. 导出报告。

尤其是：

> 局部调整、局部重排、应用方案必须区分清楚。

局部重排生成的新方案不能直接变成正式课表，仍然需要走 V3 的 apply 流程。

## 三、技术栈与组件建议

前端继续沿用项目已有技术栈。

建议：

```text
Vue3
Vite
TypeScript
Vue Router
Pinia
Axios
Element Plus
ECharts 或 vue-echarts
```

如果项目当前没有引入 ECharts，V4 可以新增，但不要为了图表引入过多复杂依赖。

### 3.1 Element Plus 组件建议

常用组件：

| 场景 | 推荐组件 |
|---|---|
| 页面布局 | `el-container` / `el-row` / `el-col` |
| 指标卡片 | `el-card` / `el-statistic` |
| 表格 | `el-table` |
| 表单 | `el-form` |
| 筛选 | `el-select` / `el-input` / `el-date-picker` |
| 弹窗 | `el-dialog` |
| 确认 | `ElMessageBox.confirm` |
| 提示 | `ElMessage` |
| 标签 | `el-tag` |
| 进度 | `el-progress` |
| 分页 | `el-pagination` |
| 抽屉 | `el-drawer` |
| 步骤条 | `el-steps` |
| 空状态 | `el-empty` |
| 骨架屏 | `el-skeleton` |

### 3.2 图表组件建议

建议封装统一图表组件：

```text
BaseBarChart.vue
BaseLineChart.vue
BasePieChart.vue
BaseRadarChart.vue
BaseHeatmapChart.vue
```

页面不要直接到处写重复的 ECharts 配置。

## 六、页面一：排课质量总览页

### 6.1 页面名称

```text
排课质量总览
```

建议文件：

```text
frontend/src/views/v4/ScheduleAnalysisOverview.vue
```

### 6.2 页面目标

展示当前学期下所有排课方案的分析入口和核心指标。

这个页面是 V4 的入口页。

### 6.3 页面布局

建议布局：

```text
顶部筛选区
  - 学期选择
  - 方案状态筛选
  - 策略筛选
  - 搜索按钮
  - 重置按钮

核心指标卡片区
  - 方案总数
  - 当前应用方案
  - 平均评分
  - 平均完成率
  - 风险方案数量

方案分析表格区
  - 方案名称
  - 状态
  - 策略
  - 总评分
  - 已排数量
  - 未排数量
  - 冲突数量
  - 是否当前应用
  - 创建时间
  - 操作
```

### 6.4 操作按钮

每行方案建议有以下按钮：

```text
分析
评分
风险
图表
报告
```

可选按钮：

```text
AI 建议
```

### 6.5 数据来源

主要接口：

```http
GET /api/v3/schedule-plans
GET /api/v4/schedule-analysis/plans/{planId}/summary
```

如果后端提供批量分析接口，可以使用批量接口；如果没有，先使用 V3 方案列表 + 点击进入单方案分析。

### 6.6 注意事项

1. 不要在总览页直接应用方案；
2. 应用方案仍然建议回到 V3 方案详情或方案对比页面；
3. 总览页只提供分析入口；
4. 当前应用方案要明显标识。

## 七、页面二：方案质量分析详情页

### 7.1 页面名称

```text
方案质量分析
```

建议文件：

```text
frontend/src/views/v4/ScheduleAnalysisDetail.vue
```

### 7.2 页面目标

展示某个方案的整体质量情况。

### 7.3 页面布局

建议布局：

```text
方案基础信息区
  - 方案名称
  - 所属学期
  - 方案状态
  - 生成策略
  - 是否当前应用
  - 创建时间
  - 应用时间

核心指标卡片区
  - 总评分
  - 已排数量
  - 未排数量
  - 冲突数量
  - 教师平均课时
  - 教室利用率
  - 高风险数量

分析结论区
  - 系统自动生成的简短结论
  - 例如：该方案完成率较高，但存在教师课时集中问题

快捷入口区
  - 查看评分详情
  - 查看风险诊断
  - 查看图表分析
  - 生成报告
```

### 7.4 评分展示建议

总评分可使用：

```text
el-progress
el-statistic
颜色标签
```

评分颜色建议：

| 分数 | 展示 |
|---:|---|
| 90 以上 | 优秀 |
| 80 - 89 | 良好 |
| 60 - 79 | 一般 |
| 60 以下 | 待优化 |

### 7.5 注意事项

1. 不要在页面中重新计算复杂算法；
2. 前端只展示后端返回结果；
3. 如果分析结果为空，应提示用户刷新分析；
4. 不要因为 V4 分析为空而影响 V3 方案详情查看。

## 八、页面三：评分详情解释页

### 8.1 页面名称

```text
评分详情解释
```

建议文件：

```text
frontend/src/views/v4/ScheduleScoreDetail.vue
```

### 8.2 页面目标

解释总评分来自哪些维度，让评分可理解、可展示、可答辩。

### 8.3 页面布局

```text
顶部方案信息
评分总览
评分明细表格
评分雷达图
评分规则说明
```

### 8.4 评分明细表格字段

| 字段 | 说明 |
|---|---|
| 评分项 | 如硬性冲突评分 |
| 得分 | 当前得分 |
| 满分 | 最大得分 |
| 权重 | 对总分影响 |
| 说明 | 评分含义 |
| 状态 | 优秀/良好/一般/待优化 |

### 8.5 页面交互

1. 鼠标悬停显示评分说明；
2. 点击评分项可展开详细解释；
3. 可跳转到相关风险列表；
4. 可跳转到对应图表。

### 8.6 注意事项

1. 不要让用户在此页面直接修改评分；
2. 评分权重配置如果还没有做后台维护，前端只展示；
3. 不要和 V3 `total_score` 产生明显矛盾；
4. 如评分明细是 V4 重新计算，应在页面显示“评分明细基于当前方案数据计算”。

集中展示某个方案存在的冲突、未排任务和潜在风险。

### 9.3 页面布局

```text
顶部风险统计卡片
  - 高风险数量

  - 低风险数量

右侧或弹窗详情
  - 风险详细解释
  - 相关课程
  - 相关教师
  - 相关班级
  - 相关教室
  - 建议处理方式
```

### 9.4 风险类型标签

建议使用不同标签展示：

```text
教师冲突
班级冲突
教室冲突
容量不足
类型不匹配
教师禁排
未排任务
教师负载过高
班级单日过载
教室利用异常
```

### 9.5 操作按钮

风险列表中可以有：

```text
查看详情
定位课程
尝试调整
```

其中：

1. 查看详情：只读；
2. 定位课程：跳转或打开课表预览；
3. 尝试调整：打开局部调整弹窗。

### 9.6 注意事项

1. 风险诊断页面不自动修复问题；
2. “尝试调整”只是进入调整流程；
3. 调整必须经过冲突检测；
4. 不允许直接一键修改正式课表。

## 十、页面五：可视化分析页

### 10.1 页面名称

```text
可视化分析
```

建议文件：

```text
frontend/src/views/v4/ScheduleCharts.vue
```

### 10.2 页面目标

通过图表展示排课方案的整体分布和资源使用情况。

### 10.3 图表建议

至少实现以下图表：

1. 教师课时分布柱状图；
2. 教室利用率排行图；
3. 班级每日课程负载图；
4. 时间段课程密度热力图；
5. 评分维度雷达图。

### 10.4 图表布局

建议使用 Tabs：

```text
教师课时
教室利用
班级负载
时间密度
评分雷达
```

或者使用卡片网格：

```text
上半部分：教师课时 + 教室利用
下半部分：班级负载 + 时间密度 + 评分雷达
```

如果图表较多，推荐 Tabs，避免页面太长。

### 10.5 图表交互

1. 图表加载中显示 loading；
2. 没有数据时显示空状态；
3. 点击图表项可查看明细；
4. 支持返回方案分析详情页；
5. 支持刷新图表数据。

### 10.6 注意事项

1. 图表只展示后端统计数据；
2. 前端不要自己做复杂业务计算；
3. 图表数据为空时不要报错；
4. 图表组件要能自适应窗口宽度；
5. ECharts 初始化时注意组件销毁，避免内存泄露。

## 十一、页面六：局部调整弹窗

### 11.1 页面名称

局部调整建议先做成弹窗或抽屉，不建议一开始做成独立大页面。

建议组件：

```text
frontend/src/components/v4/ScheduleAdjustDialog.vue
```

或者：

```text
frontend/src/views/v4/components/ScheduleAdjustDialog.vue
```

### 11.2 入口位置

局部调整入口可以放在：

1. V3 方案详情页；
2. V4 风险诊断页；
3. V4 图表明细页；
4. 正式课表页。

### 11.3 弹窗内容

```text
当前课程信息
  - 课程名称
  - 教师
  - 班级
  - 当前时间
  - 当前教室

调整表单
  - 新星期
  - 新节次
  - 新教室
  - 备注

冲突检测结果
  - 是否可调整
  - 冲突数量
  - 冲突说明
  - 建议
```

### 11.4 操作按钮

```text
检测冲突
保存调整
取消
```

如果存在冲突，保存时必须二次确认：

```text
调整后存在冲突，是否仍然保存？
```

### 11.5 数据流程

```text
用户选择新时间/教室
点击检测冲突
调用 /api/v4/schedule-adjustments/check
展示冲突结果
无冲突则允许保存
有冲突则需要二次确认
调用 /api/v4/schedule-adjustments/apply
保存成功后刷新当前页面数据
```

### 11.6 注意事项

1. 检测冲突和保存调整是两个接口；
2. 不要只在前端判断冲突；
3. 保存后必须刷新风险和分析数据；
4. 如果调整的是正式课表，要提示“该操作会导致正式课表与来源方案不完全一致”；
5. 如果调整的是方案项，不要直接影响正式课表。

## 十二、页面七：课程锁定管理页

### 12.1 页面名称

```text
课程锁定管理
```

建议文件：

```text
frontend/src/views/v4/ScheduleLockManage.vue
```

### 12.2 页面目标

管理某个方案中被人工确认、不参与局部重排的课程安排。

### 12.3 页面布局

```text
方案信息区
锁定统计区
已锁定课程表格

```

### 12.4 已锁定课程表格字段

| 字段 | 说明 |

4. 锁定信息必须以后端为准；

export function getScheduleAnalysisSummary(planId: number) {

export function getScheduleRisks(planId: number, params?: any) {

## 二十八、总结

V4 前端的核心是：

```text
把 V3 生成的排课方案展示得更清楚；
把方案质量解释得更明白；
把风险诊断展示得更直观；
把局部调整做得更安全；
把报告和 AI 建议作为辅助亮点。
```

V4 前端不应该变成另一个复杂的排课系统，也不应该破坏 V3 生成、应用、回滚的主流程。

最终目标是让系统从：

```text
能生成课表
```

升级为：

```text
能分析课表、解释问题、辅助优化、展示结果。
```
