# V2_CLAUDE追加规则

## 1. 使用方式

本文件用于在 V1 `CLAUDE.md` 的基础上追加 V2 开发规则。

如果项目根目录已经存在 `CLAUDE.md`，不要直接覆盖原文件。建议做法：

```text
方式一：把本文件内容追加到原 CLAUDE.md 后面
方式二：保留原 CLAUDE.md，同时在 docs/ 中保存本文件，并要求 AI 开发前同时阅读
```

推荐优先级：

```text
CLAUDE.md
↓
V2_CLAUDE追加规则.md
↓
V2_01_项目需求说明_PRD.md
↓
V2_07_开发阶段计划.md
```

如果 V1 文档和 V2 文档有冲突：

- V1 基础功能规则继续保留
- V2 新增功能以 V2 文档为准
- 不允许推翻 V1 已完成的稳定功能

## 2. 当前项目版本

当前项目进入：

```text
V2：规则化自动排课与排课优化版
```

V2 是在 V1 基础上的增强版本，不是重写项目。

V1 已经确定的核心能力：

```text
基础数据管理
教学任务管理
手动排课
冲突检测
课表查询
```

V2 新增核心能力：

```text
教师禁排时间
排课规则配置
规则化自动排课
未排任务记录
排课冲突报告
课表评分
Excel 导出
```

## 3. V2 绝对不能做的事

V2 阶段禁止做以下内容：

```text
遗传算法
模拟退火
Timefold Solver
复杂回溯搜索
多目标优化求解
学生选课
教师端
学生端
考试排课
调课审批
多学期管理
多校区管理
移动端适配
AI 排课建议
```

这些内容最多作为 V3 或论文展望，不允许混进 V2 实现。

## 4. V2 技术栈不变

继续使用 V1 技术栈，不得擅自更换。

后端：

```text
Java 17
Spring Boot 3
MyBatis Plus
MySQL
JWT
Maven
```

前端：

```text
Vue 3
Vite
TypeScript
Element Plus
Vue Router
Pinia
Axios
```

不要引入大型复杂依赖，除非文档明确允许。

Excel 导出可以选择：

```text
EasyExcel
或 Apache POI
```

优先选择实现简单、稳定、便于维护的方案。

## 5. V2 新增数据库表

V2 新增表：

```text
teacher_unavailable_time
schedule_rule_config
auto_schedule_batch
unscheduled_task
schedule_conflict_report
schedule_score_report
```

V2 需要扩展 V1 的 `schedule` 表：

```text
source_type
batch_id
```

说明：

```text
source_type = MANUAL 表示手动排课
source_type = AUTO 表示自动排课
batch_id 用于关联自动排课批次
```

不要删除或重建 V1 表。

## 7. 自动排课算法边界

V2 自动排课只能做“规则化遍历算法”。

允许实现：

```text
任务排序
时间段排序
教室排序
硬约束检测
软约束排序
未排原因记录
自动排课批次记录
```

不允许实现：

```text
遗传算法
模拟退火
复杂递归回溯
Timefold Solver
OptaPlanner
数学优化求解器
```

V2 自动排课目标不是全局最优，而是：

```text
尽可能自动生成无明显冲突的课表
无法安排的任务要记录原因
管理员可以后续手动调整
```

## 8. 自动排课必须复用冲突检测

不要在自动排课里重新写一套完全独立的冲突检测逻辑。

推荐结构：

```text
ScheduleConflictService
AutoScheduleService
ScheduleRuleService
TeacherUnavailableTimeService
```

`ScheduleConflictService` 应该同时服务：

```text
手动排课
自动排课
冲突报告
```

这样可以避免规则不一致。

## 9. V2 硬约束

自动排课必须检查以下硬约束：

```text
同一教师同一时间不能有两门课
同一班级同一时间不能有两门课
同一教室同一时间不能安排两门课
班级人数不能大于教室容量
实验课必须安排实验室
机房课必须安排机房
教师禁排时间不能排课
停用教师不能参与排课
停用班级不能参与排课
停用教室不能参与排课
教学任务不能超过每周课时
```

硬约束不满足时，不能保存排课记录。

## 10. V2 规则配置

排课规则配置第一版只做全局配置。

默认规则：

```text
教师每天最多课程大节数：3
班级每天最多课程大节数：4
优先上午排课：开启
避免周五下午：开启
允许同一课程同一天重复出现：关闭
```

不要做过度复杂的按学院、专业、班级、课程类型分别配置。

## 11. 教师禁排时间规则

教师禁排时间必须影响：

```text
手动排课
自动排课
冲突报告
课表评分
```

保存手动排课时，如果命中教师禁排时间，必须提示：

```text
排课失败：张老师在周三第5-6节设置了禁排时间
```

自动排课时，如果某时间段命中教师禁排时间，应跳过该时间段。

## 12. 自动排课批次规则

每次执行自动排课，都必须创建批次记录。

批次应记录：

```text
批次号
参与任务数
成功任务数
失败任务数
生成排课记录数
是否清空旧排课
执行状态
开始时间
结束时间
执行说明
```

批次状态建议：

```text
RUNNING
SUCCESS
PARTIAL
FAILED
```

如果部分任务未排完，但系统正常执行完成，应设置为：

```text
PARTIAL
```

不要把“部分任务未排完”当成系统异常。

## 13. 未排任务规则

自动排课失败或任务未排满时，必须记录未排任务。

未排任务至少包含：

```text
批次ID
教学任务ID
课程ID
教师ID
班级ID
需要大节数
已排大节数
剩余大节数
未排原因类型
未排原因说明
```

未排原因不能只写“失败”。

必须尽量明确，例如：

```text
没有可用时间段
没有符合课程类型的教室
所有可用教室容量不足
教师禁排时间限制
教师时间冲突
班级时间冲突
排课规则限制过严
```

## 14. 清空排课规则

自动排课允许两个清空选项：

```text
clearOldAutoSchedule
clearAllSchedule
```

规则：

```text
clearOldAutoSchedule = true
只清空 source_type = AUTO 的旧自动排课记录

clearAllSchedule = true
清空 AUTO 和 MANUAL 的全部排课记录
```

前端对 `clearAllSchedule` 必须做危险操作二次确认。

默认不允许静默删除手动排课记录。

## 15. 自动排课返回结果

自动排课接口必须返回清晰结果：

```text
batchId
batchNo
totalTaskCount
successTaskCount
failedTaskCount
generatedScheduleCount
status
message
```

不要只返回 `true` 或 `success`。

## 16. 冲突报告规则

冲突报告是对当前课表的全局扫描。

必须检测：

```text
教师冲突
班级冲突
教室冲突
容量不足
教室类型不匹配
教师禁排时间冲突
教学任务未排满
教师当天课程过多
班级当天课程过多
```

每条报告必须包含：

```text
冲突类型
冲突对象
冲突时间
冲突说明
处理建议
```

处理建议必须能让用户看懂。

## 17. 课表评分规则

课表评分采用百分制。

评分结果至少包含：

```text
总分
等级
硬冲突数量
未排满任务数量
教师超负荷数量
班级超负荷数量
周五下午课程数量
扣分详情
优化建议
```

评分等级：

```text
90-100：优秀
80-89：良好
70-79：一般
60-69：较差
60以下：需要调整
```

课表评分必须可解释，不能只给一个分数。

## 18. Excel 导出规则

支持导出：

```text
班级课表 Excel
教师课表 Excel
教室占用表 Excel
```

导出要求：

```text
文件格式为 .xlsx
文件名包含对象名称和日期
表格结构和前端周课表一致
空时间段保持空白
导出接口需要登录认证
```

不要为了导出功能破坏课表查询接口。

## 20. 前端交互要求

前端必须做到：

```text
自动排课前有确认提示

自动排课完成后显示执行结果
未排任务原因完整展示
冲突报告说明清楚
课表评分显示扣分项

```

不要只在控制台打印错误。

## 23. 开发行为准则

开发 V2 时必须遵守：

```text
每次只做一个阶段
每个阶段完成后保证项目可启动
不要一次性生成大量不可运行代码
不要擅自改 V1 稳定功能
不要把规则只写在前端
不要隐藏自动排课失败原因
不要静默覆盖手动排课
不要为了展示效果牺牲业务正确性
```

如果文档不明确，优先选择简单、稳定、可解释的实现。
