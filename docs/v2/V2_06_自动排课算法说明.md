# V2_06_自动排课算法说明

## 1. 算法定位

V2 自动排课采用“规则化遍历算法”。

它不是遗传算法，不是 Timefold Solver，不是数学最优化求解器。

V2 自动排课的目标是：

```text
在已有教学任务、时间段、教室资源中，
根据规则自动寻找可用位置，
尽可能生成无冲突课表。
```

该算法适合毕业设计第一阶段智能化升级，优点是：

- 容易实现
- 容易解释
- 容易调试
- 适合答辩讲解
- 不会把项目复杂度拉爆

## 2. 核心思想

系统把每个教学任务拆成若干个需要安排的大节。

例如：

```text
Java程序设计
每周课时：4
一个 time_slot 表示 2 小节
所以需要排 2 个大节
```

然后系统依次为每个大节寻找：

```text
合适的时间段 + 合适的教室
```

如果满足所有硬性约束，则保存排课结果。  
如果找不到合适位置，则记录未排原因。

## 3. 输入数据

自动排课需要读取以下数据：

### 3.1 教学任务

来自 `teaching_task` 表。

需要字段：

```text
任务ID
课程ID
教师ID
班级ID
每周课时
是否需要连续排课
任务状态
```

### 3.2 课程信息

来自 `course` 表。

需要字段：

```text
课程类型
每周课时
```

### 3.3 教师信息

来自 `teacher` 表。

需要字段：

```text
教师ID
教师姓名
状态
```

### 3.4 班级信息

来自 `class_info` 表。

需要字段：

```text
班级ID
班级人数
状态
```

### 3.5 教室信息

来自 `classroom` 表。

需要字段：

```text
教室ID
教室容量
教室类型
状态
```

### 3.6 时间段信息

来自 `time_slot` 表。

V2 使用 V1 固定时间段：

```text
周一到周五
每天 4 个大节
共 20 个时间段
```

### 3.7 教师禁排时间

来自 `teacher_unavailable_time` 表。

### 3.8 排课规则

来自 `schedule_rule_config` 表。

## 4. 输出数据

自动排课会产生：

### 4.1 排课结果

写入 `schedule` 表。

自动排课生成的记录：

```text
source_type = AUTO
batch_id = 当前自动排课批次ID
```

### 4.2 自动排课批次

写入 `auto_schedule_batch` 表。

记录：

```text
批次号
参与任务数
成功任务数
失败任务数
生成排课记录数
执行状态
开始时间
结束时间
```

### 4.3 未排任务记录

写入 `unscheduled_task` 表。

记录：

```text
教学任务
剩余未排大节数
未排原因类型
未排原因说明
```

## 5. 约束类型

自动排课中的规则分为两类：

```text
硬约束
软约束
```

## 6. 硬约束

硬约束必须满足，不满足就不能排课。

V2 硬约束包括：

### 6.1 教师时间冲突

同一教师同一时间段不能有两门课。

### 6.2 班级时间冲突

同一班级同一时间段不能有两门课。

### 6.3 教室时间冲突

同一教室同一时间段不能安排两门课。

### 6.4 教室容量限制

班级人数不能大于教室容量。

### 6.5 教室类型限制

课程类型和教室类型必须匹配。

建议规则：

```text
普通课：普通教室 / 多媒体教室 / 实验室 / 机房 均可
实验课：必须实验室
机房课：必须机房
体育课：第一版可不限制教室，或指定普通教室
```

### 6.6 教师禁排时间

教师在禁排时间段不能排课。

### 6.7 停用资源限制

停用教师、停用班级、停用教室不能参与排课。

### 6.8 教学任务课时限制

教学任务已排大节数不能超过需要大节数。

## 7. 软约束

软约束不是绝对禁止，但会影响排课顺序或评分。

V2 软约束包括：

### 7.1 优先上午排课

如果开启该规则，自动排课优先尝试：

```text
第1-2节
第3-4节
```

再尝试：

```text
第5-6节
第7-8节
```

### 7.2 尽量避免周五下午

如果开启该规则，系统将周五第5-6节和第7-8节放到较后尝试。

注意：

这不是绝对禁止。  
如果其他时间无法安排，仍然可以使用周五下午。

### 7.3 教师每天最多课程数

如果启用：

```text
教师每天最多 3 个大节
```

超过则不安排或降低优先级。

V2 建议先作为硬性限制处理，便于实现。

### 7.4 班级每天最多课程数

如果启用：

```text
班级每天最多 4 个大节
```

超过则不安排。

### 7.5 同一课程同一天重复限制

如果不允许同一课程同一天重复出现，则同一班级同一课程一天内只能安排一次。

## 8. 自动排课整体流程

### 8.1 流程图文字版

```text
开始自动排课
↓
创建自动排课批次
↓
读取排课规则
↓
读取待排教学任务
↓
计算每个任务还需要排几个大节
↓
对任务排序
↓
遍历教学任务
↓
  遍历该任务需要安排的大节数
  ↓
  获取排序后的时间段列表
  ↓
  遍历时间段
  ↓
    获取符合课程类型和容量的教室列表
    ↓
    遍历教室
    ↓
      执行冲突检测
      ↓
      如果通过：保存排课记录，进入下一个大节
      如果不通过：尝试下一个教室或时间段
  ↓
  如果无法安排：记录未排任务原因
↓
更新自动排课批次结果
↓
结束
```

## 9. 任务排序策略

为了提高成功率，建议先安排更难排的任务。

排序规则建议：

```text
1. 实验课、机房课优先
2. 班级人数多的任务优先
3. 每周课时多的任务优先
4. 教师禁排时间多的任务优先
```

原因：

- 实验课和机房课可用教室少
- 人数多的班级可用教室少
- 每周课时多的任务更难安排
- 教师禁排时间多会压缩可用时间

## 10. 时间段排序策略

默认时间段为 20 个。

如果开启“优先上午排课”，排序为：

```text
周一第1-2节
周一第3-4节
周二第1-2节
周二第3-4节
...
周五第1-2节
周五第3-4节
周一第5-6节
周一第7-8节
...
周五第5-6节
周五第7-8节
```

如果开启“避免周五下午”，则周五第5-6节和周五第7-8节放到最后。

## 11. 教室排序策略

建议教室排序：

```text
1. 类型匹配的教室优先
2. 容量刚好满足的教室优先
3. 容量更大的教室靠后
```

这样可以避免小班级占用过大的教室。

示例：

```text
班级人数 45
教室容量 50、80、120
优先选择 50 人教室
```

## 12. 冲突检测方法

自动排课不要重复写一套冲突逻辑。

应该复用 V1 的冲突检测服务，并在 V2 扩展。

推荐服务：

```text
ScheduleConflictService
```

新增方法：

```text
checkForAutoSchedule(task, timeSlot, classroom, ruleConfig)
```

检测内容：

```text
教师冲突
班级冲突
教室冲突
容量限制
教室类型限制
教师禁排时间
教师每天最多课程数
班级每天最多课程数
同一课程同一天重复限制
```

## 13. 伪代码

```java
public AutoScheduleResult runAutoSchedule(AutoScheduleRequest request) {
    AutoScheduleBatch batch = createBatch(request);

    List<ScheduleRule> rules = loadRules();
    List<TeachingTask> tasks = loadPendingTasks(request.getTaskIds());
    List<TimeSlot> timeSlots = sortTimeSlots(loadTimeSlots(), rules);
    List<Classroom> classrooms = loadEnabledClassrooms();

    int generatedCount = 0;
    int successTaskCount = 0;
    int failedTaskCount = 0;

    for (TeachingTask task : sortTasks(tasks)) {
        int requiredSlots = calculateRequiredSlots(task);
        int scheduledSlots = countScheduledSlots(task);
        int remainingSlots = requiredSlots - scheduledSlots;

        int currentSuccess = 0;
        String lastFailReason = "";

        for (int i = 0; i < remainingSlots; i++) {
            boolean arranged = false;

            for (TimeSlot slot : timeSlots) {
                List<Classroom> matchedRooms = sortClassrooms(
                    filterClassrooms(task, classrooms),
                    task
                );

                for (Classroom room : matchedRooms) {
                    ConflictResult check = conflictService.checkForAutoSchedule(
                        task, slot, room, rules
                    );

                    if (check.isPassed()) {
                        saveSchedule(task, slot, room, batch.getId(), "AUTO");
                        generatedCount++;
                        currentSuccess++;
                        arranged = true;
                        break;
                    } else {
                        lastFailReason = check.getMessage();
                    }
                }

                if (arranged) {
                    break;
                }
            }

            if (!arranged) {
                saveUnscheduledTask(task, batch.getId(), lastFailReason);
                break;
            }
        }

        if (currentSuccess > 0) {
            successTaskCount++;
        }

        if (currentSuccess < remainingSlots) {
            failedTaskCount++;
        }
    }

    updateBatchResult(batch, successTaskCount, failedTaskCount, generatedCount);

    return buildResult(batch);
}
```

## 14. 未排原因记录策略

如果某个任务无法安排，需要记录原因。

### 14.1 简单策略

记录最后一次失败原因。

优点：

- 实现简单
- 够毕业设计使用

缺点：

- 不一定是最准确原因

### 14.2 更推荐策略

统计失败原因出现次数，选择出现最多的原因作为主原因。

例如：

```text
教师冲突出现 5 次
教室容量不足出现 12 次
教室类型不匹配出现 2 次
```

最终原因：

```text
教室容量不足
```

## 15. 清空旧排课策略

自动排课请求中有两个清空选项。

### 15.1 clearOldAutoSchedule

只清空旧自动排课记录：

```text
source_type = AUTO
```

不删除手动排课记录。

推荐默认开启。

### 15.2 clearAllSchedule

清空全部排课记录：

```text
source_type = AUTO
source_type = MANUAL
```

这是危险操作，前端必须二次确认。

推荐默认关闭。

## 16. 连续排课说明

V2 中 `need_continuous` 字段可以暂时简化处理。

如果 `need_continuous = true`：

- 由于一个 time_slot 已经代表两节连上课
- V2 可以认为天然满足连续排课

暂不实现跨多个 time_slot 的连续排课。

## 17. 算法局限性

V2 自动排课是启发式规则算法，不保证全局最优。

可能出现：

```text
前面任务占用了较好时间
后面任务无法安排
```

这是正常现象。

可以通过以下方式改善：

- 优先安排难排任务
- 适当调整时间段排序
- 适当放宽规则
- 删除部分手动排课后重新排
- 后续 V3 引入更复杂算法

## 18. 答辩解释话术

可以这样解释：

```text
本系统在 V2 中实现了基于规则约束的自动排课算法。
系统将教师、班级、教室和时间段视为排课资源，
将教师冲突、班级冲突、教室冲突、容量限制、教室类型限制和教师禁排时间作为硬约束，
将优先上午排课、避免周五下午、教师课程均衡等作为软约束。
自动排课时，系统优先安排资源受限程度较高的教学任务，
再按照规则排序后的时间段和教室进行遍历匹配，
一旦找到满足约束的位置则生成排课记录。
对于无法安排的任务，系统会记录未排原因，便于管理员后续手动调整。
```

## 19. 不要做的事

V2 阶段不要做：

```text
遗传算法
模拟退火
Timefold Solver
复杂回溯搜索
多目标优化求解
学生选课冲突优化
考试排课算法
```

这些放到 V3 或论文展望即可。

## 20. 最终目标

V2 自动排课达到以下效果即可：

```text
点击一键自动排课
系统自动生成大部分课程安排
自动避开明显冲突
无法安排的任务有原因
管理员可以查看和手动调整
```

这已经足够作为毕业设计中的“智能排课”核心功能。
