# V2_04_接口设计

## 1. 接口设计原则

V2 接口继续沿用 V1 风格：

```text
/api
```

统一返回格式：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

V2 新增接口主要服务于：

- 教师禁排时间
- 排课规则配置
- 自动排课
- 未排任务
- 冲突报告
- 课表评分
- Excel 导出

## 2. 教师禁排时间接口

### 2.1 查询禁排时间列表

```text
GET /api/teacher-unavailable-times
```

查询参数：

```text
teacherId
teacherName
timeSlotId
status
page
size
```

返回示例：

```json
{
  "records": [
    {
      "id": 1,
      "teacherId": 1,
      "teacherName": "张老师",
      "timeSlotId": 10,
      "timeSlotName": "周三第5-6节",
      "reason": "教研活动",
      "status": 1
    }
  ],
  "total": 1
}
```

### 2.2 新增禁排时间

```text
POST /api/teacher-unavailable-times
```

请求：

```json
{
  "teacherId": 1,
  "timeSlotId": 10,
  "reason": "教研活动",
  "status": 1,
  "remark": ""
}
```

### 2.3 编辑禁排时间

```text
PUT /api/teacher-unavailable-times/{id}
```

### 2.4 删除禁排时间

```text
DELETE /api/teacher-unavailable-times/{id}
```

### 2.5 启用/停用禁排时间

```text
PUT /api/teacher-unavailable-times/{id}/status
```

请求：

```json
{
  "status": 0
}
```

## 3. 排课规则配置接口

### 3.1 获取规则配置

```text
GET /api/schedule-rules
```

返回示例：

```json
[
  {
    "ruleKey": "TEACHER_MAX_DAILY_SLOTS",
    "ruleValue": "3",
    "ruleName": "教师每天最多课程大节数",
    "enabled": 1
  },
  {
    "ruleKey": "PRIORITIZE_MORNING",
    "ruleValue": "true",
    "ruleName": "是否优先上午排课",
    "enabled": 1
  }
]
```

### 3.2 更新规则配置

```text
PUT /api/schedule-rules
```

请求：

```json
[
  {
    "ruleKey": "TEACHER_MAX_DAILY_SLOTS",
    "ruleValue": "3",
    "enabled": 1
  },
  {
    "ruleKey": "AVOID_FRIDAY_AFTERNOON",

]
```

### 3.3 恢复默认规则

```text
POST /api/schedule-rules/reset-default
```

## 4. 自动排课接口

### 4.1 执行自动排课

```text
POST /api/auto-schedule/run
```

请求：

```json
{
  "taskIds": [1, 2, 3],
  "clearOldAutoSchedule": true,
  "clearAllSchedule": false
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| taskIds | 参与自动排课的教学任务ID列表，空数组表示全部未排满任务 |
| clearOldAutoSchedule | 是否清空旧的自动排课记录 |
| clearAllSchedule | 是否清空全部排课记录，包含手动排课，默认不建议开启 |

响应：

```json
{
  "batchId": 1,
  "batchNo": "AUTO202605110001",
  "totalTaskCount": 20,
  "successTaskCount": 17,
  "failedTaskCount": 3,
  "generatedScheduleCount": 34,
  "status": "PARTIAL",
  "message": "自动排课完成，部分任务未排满"
}
```

### 4.2 查询自动排课批次

```text
GET /api/auto-schedule/batches
```

查询参数：

```text
batchNo
status
startTime
endTime
page
size
```

### 4.3 查询批次详情

```text
GET /api/auto-schedule/batches/{batchId}
```

返回：

```json
{
  "id": 1,
  "batchNo": "AUTO202605110001",
  "totalTaskCount": 20,
  "successTaskCount": 17,
  "failedTaskCount": 3,
  "generatedScheduleCount": 34,
  "status": "PARTIAL",
  "message": "自动排课完成，部分任务未排满",
  "startTime": "2026-05-11 10:00:00",
  "endTime": "2026-05-11 10:00:03"
}
```

### 4.4 清空自动排课结果

```text
DELETE /api/auto-schedule/batches/{batchId}/schedules
```

说明：

只删除该批次自动生成的排课记录，不删除手动排课记录。

## 5. 未排任务接口

```text
GET /api/unscheduled-tasks
```

查询参数：

```text
batchId
courseName
teacherName
className
reasonType
page
size
```

返回示例：

```json
{
  "records": [
    {
      "id": 1,
      "batchId": 1,
      "taskId": 5,
      "courseName": "数据库原理",
      "teacherName": "李老师",
      "className": "计科2班",
      "requiredSlots": 2,
      "scheduledSlots": 1,
      "remainingSlots": 1,
      "reasonType": "NO_AVAILABLE_TIME",
      "reasonMessage": "未找到满足教师、班级、教室规则的可用时间段"
    }
  ],
  "total": 1
}
```

### 5.2 查询某批次未排任务

```text
GET /api/auto-schedule/batches/{batchId}/unscheduled-tasks
```

### 5.3 清空未排任务记录

```text
DELETE /api/unscheduled-tasks
```

可选参数：

```text
batchId
```

## 6. 冲突报告接口

### 6.1 生成冲突报告

```text
POST /api/schedule-conflict-reports/generate
```

说明：

扫描当前 schedule 表，生成新的冲突报告。

请求可为空：

```json
{}
```

响应：

```json
{
  "reportNo": "CR202605110001",
  "conflictCount": 5,
  "message": "检测完成，发现 5 条问题"
}
```

### 6.2 查询冲突报告

```text
GET /api/schedule-conflict-reports
```

查询参数：

```text
reportNo
conflictType
objectType
objectName
page
size
```

返回示例：

```json
{
  "records": [
    {
      "id": 1,
      "reportNo": "CR202605110001",
      "conflictType": "TEACHER_CONFLICT",
      "objectType": "TEACHER",
      "objectName": "张老师",
      "timeSlotName": "周一第1-2节",
      "description": "张老师在周一第1-2节存在两条课程安排",
      "suggestion": "建议调整其中一门课程到其他时间段"
    }
  ],
  "total": 1
}
```

### 6.3 清空冲突报告

```text
DELETE /api/schedule-conflict-reports
```

可选参数：

```text
reportNo
```

  "gradeName": "良好",
  "conflictCount": 0,
  "unfinishedTaskCount": 2,

```text
GET /api/schedule-score/reports
```

查询参数：

```text
grade
startTime
endTime
page
size
```

## 8. Excel 导出接口

### 8.1 导出班级课表

```text
GET /api/export/timetables/classes/{classId}
```

响应：

```text
文件流：class_timetable_{classId}.xlsx
```

### 8.2 导出教师课表

```text
GET /api/export/timetables/teachers/{teacherId}
```

响应：

```text
文件流：teacher_timetable_{teacherId}.xlsx
```

### 8.3 导出教室占用表

```text
GET /api/export/timetables/classrooms/{classroomId}
```

响应：

```text
文件流：classroom_timetable_{classroomId}.xlsx
```

### 8.4 导出注意事项

- 文件名应包含对象名称和导出日期
- 表格结构应与前端课表一致
- 没有课程的时间段显示为空
- 导出接口需要登录认证

## 9. V1 接口扩展建议

### 9.1 排课列表增加字段

V2 中 `/api/schedules` 建议返回：

```json
{
  "sourceType": "AUTO",
  "sourceTypeName": "自动排课",
  "batchId": 1,
  "batchNo": "AUTO202605110001"
}
```

### 9.2 手动排课增加禁排检查

V1 已有：

```text
POST /api/schedules
```

V2 需要在此接口保存时额外检查：

```text
教师禁排时间
教师每天最多课程数
班级每天最多课程数
同一课程同一天重复限制
```

其中是否检查规则限制，可根据具体设计决定。至少必须检查教师禁排时间。

## 10. 自动排课错误返回示例

### 10.1 参数错误

```json
{
  "code": 400,
  "message": "自动排课失败：请选择教学任务或使用全部未排满任务",
  "data": null
}
```

### 10.2 任务不存在

```json
{
  "code": 400,
  "message": "自动排课失败：部分教学任务不存在",
  "data": null
}
```

### 10.3 资源不足

```json
{
  "code": 200,
  "message": "自动排课完成，但存在未排任务",
  "data": {
    "status": "PARTIAL",
    "failedTaskCount": 3
  }
}
```

注意：部分任务未排完不一定是接口错误，应返回正常响应并提示用户查看未排任务。

## 11. 接口开发优先级

建议开发顺序：

```text
1. 教师禁排时间接口
2. 排课规则配置接口
3. 自动排课接口
4. 未排任务接口
5. 冲突报告接口
6. 课表评分接口
7. Excel 导出接口
```

不要先做 Excel 导出。自动排课和未排任务才是 V2 核心。
