# V2_03_数据库设计

## 1. 设计原则

V2 不推翻 V1 的数据库结构，而是在 V1 的 8 张核心表基础上做扩展。

V1 已有核心表：

```text
sys_user
teacher
class_info
classroom
course
teaching_task
time_slot
schedule
```

V2 新增表主要用于支持：

- 教师禁排时间
- 排课规则配置
- 自动排课批次
- 未排任务记录
- 冲突报告
- 课表评分

## 2. V2 新增表总览

建议新增 6 张表：

```text
teacher_unavailable_time      教师禁排时间表
schedule_rule_config          排课规则配置表
auto_schedule_batch           自动排课批次表
unscheduled_task              未排任务表
schedule_conflict_report      排课冲突报告表
schedule_score_report         课表评分报告表
```

## 3. teacher_unavailable_time 教师禁排时间表

### 3.1 表说明

记录教师在哪些时间段不可排课。

手动排课和自动排课都必须检查此表。

### 3.2 字段设计

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| teacher_id | bigint | 教师ID |
| time_slot_id | bigint | 时间段ID |
| reason | varchar(255) | 禁排原因 |
| status | tinyint | 状态：1启用，0停用 |
| remark | varchar(255) | 备注 |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |
| deleted | tinyint | 逻辑删除 |

### 3.3 约束建议

- teacher_id + time_slot_id 在未删除数据中不能重复
- teacher_id 必须存在于 teacher 表
- time_slot_id 必须存在于 time_slot 表
- 停用教师不能新增禁排时间

### 3.4 示例数据

```text
张老师 / 周三第5-6节 / 教研活动
李老师 / 周五第7-8节 / 固定会议
```

## 4. schedule_rule_config 排课规则配置表

### 4.1 表说明

用于保存自动排课的全局规则配置。

V2 先做全局配置，不做按学院、专业、班级的复杂配置。

### 4.2 字段设计

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| rule_key | varchar(100) | 规则键 |
| rule_value | varchar(100) | 规则值 |
| rule_name | varchar(100) | 规则名称 |
| description | varchar(255) | 规则说明 |
| enabled | tinyint | 是否启用：1启用，0停用 |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |

### 4.3 默认规则

| rule_key | 默认值 | 说明 |
|---|---|---|
| TEACHER_MAX_DAILY_SLOTS | 3 | 教师每天最多课程大节数 |
| CLASS_MAX_DAILY_SLOTS | 4 | 班级每天最多课程大节数 |
| PRIORITIZE_MORNING | true | 是否优先上午排课 |
| AVOID_FRIDAY_AFTERNOON | true | 是否避免周五下午 |
| ALLOW_SAME_COURSE_SAME_DAY | false | 是否允许同一课程同一天重复出现 |

### 4.4 说明

规则值统一保存为字符串，业务层根据 rule_key 转换成 boolean 或 int。

## 5. auto_schedule_batch 自动排课批次表

### 5.1 表说明

每次点击“一键自动排课”时，生成一个自动排课批次。

用于记录本次自动排课的执行结果，方便查看历史记录。

### 5.2 字段设计

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| batch_no | varchar(50) | 批次号 |
| total_task_count | int | 参与排课任务数 |
| success_task_count | int | 成功排课任务数 |
| failed_task_count | int | 未排任务数 |
| generated_schedule_count | int | 生成排课记录数 |
| clear_old_schedule | tinyint | 是否清空旧排课：1是，0否 |
| status | varchar(30) | 状态 |
| message | varchar(500) | 执行结果说明 |
| start_time | datetime | 开始时间 |
| end_time | datetime | 结束时间 |
| create_time | datetime | 创建时间 |

### 5.3 status 建议值

```text
RUNNING     执行中
SUCCESS     执行完成
PARTIAL     部分成功
FAILED      执行失败
```

### 5.4 说明

如果自动排课未能安排全部任务，但系统正常执行完成，建议状态为 PARTIAL。

## 6. unscheduled_task 未排任务表

### 6.1 表说明

记录自动排课过程中没有成功安排的任务及原因。

### 6.2 字段设计

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| batch_id | bigint | 自动排课批次ID |
| task_id | bigint | 教学任务ID |
| course_id | bigint | 课程ID |
| teacher_id | bigint | 教师ID |
| class_id | bigint | 班级ID |
| required_slots | int | 需要排的大节数 |
| scheduled_slots | int | 已排大节数 |
| remaining_slots | int | 剩余未排大节数 |
| reason_type | varchar(50) | 未排原因类型 |
| reason_message | varchar(500) | 未排原因说明 |
| create_time | datetime | 创建时间 |

### 6.3 reason_type 建议值

```text
NO_AVAILABLE_TIME              没有可用时间段
NO_MATCHED_CLASSROOM           没有符合类型的教室
CLASSROOM_CAPACITY_NOT_ENOUGH  教室容量不足
TEACHER_UNAVAILABLE            教师禁排时间限制
TEACHER_CONFLICT               教师时间冲突
CLASS_CONFLICT                 班级时间冲突
ROOM_CONFLICT                  教室时间冲突
RULE_LIMIT                     排课规则限制
UNKNOWN                        未知原因
```

### 6.4 说明

未排任务不一定代表系统错误，可能是排课资源不足或规则限制过严。

## 7. schedule_conflict_report 排课冲突报告表

### 7.1 表说明

记录“一键检测当前课表”生成的冲突报告。

### 7.2 字段设计

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| report_no | varchar(50) | 报告编号 |
| conflict_type | varchar(50) | 冲突类型 |
| object_type | varchar(50) | 冲突对象类型 |
| object_id | bigint | 冲突对象ID |
| object_name | varchar(100) | 冲突对象名称 |
| time_slot_id | bigint | 时间段ID |
| related_schedule_ids | varchar(255) | 相关排课记录ID |
| description | varchar(500) | 冲突说明 |
| suggestion | varchar(500) | 处理建议 |
| create_time | datetime | 创建时间 |

### 7.3 conflict_type 建议值

```text
TEACHER_CONFLICT               教师冲突
CLASS_CONFLICT                 班级冲突
ROOM_CONFLICT                  教室冲突
CAPACITY_CONFLICT              容量冲突
ROOM_TYPE_CONFLICT             教室类型冲突
TEACHER_UNAVAILABLE_CONFLICT   教师禁排冲突
TASK_NOT_FULLY_SCHEDULED       教学任务未排满
TEACHER_DAILY_OVERLOAD         教师当天课程过多
CLASS_DAILY_OVERLOAD           班级当天课程过多
```

### 7.4 object_type 建议值

```text
TEACHER
CLASS
CLASSROOM
TASK
SCHEDULE
```

## 8. schedule_score_report 课表评分报告表

### 8.1 表说明

保存当前课表评分结果。

评分主要用于展示系统排课质量，不作为强制业务规则。

### 8.2 字段设计

| 字段名 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| score | int | 总分，0-100 |
| grade | varchar(20) | 等级 |
| conflict_count | int | 硬冲突数量 |
| unfinished_task_count | int | 未排满任务数量 |
| teacher_overload_count | int | 教师超负荷数量 |
| class_overload_count | int | 班级超负荷数量 |
| friday_afternoon_count | int | 周五下午课程数量 |
| deduction_detail | text | 扣分详情 |
| suggestion | text | 优化建议 |
| create_time | datetime | 创建时间 |

### 8.3 grade 建议值

```text
EXCELLENT   优秀
GOOD        良好
NORMAL      一般
POOR        较差
BAD         需要调整
```

对应分数：

```text
90-100：优秀
80-89：良好
70-79：一般
60-69：较差
60以下：需要调整
```

## 9. V1 表的扩展建议

### 9.1 schedule 表建议扩展字段

V2 可以给 schedule 表新增字段：

| 字段名 | 类型 | 说明 |
|---|---|---|
| source_type | varchar(30) | 来源：MANUAL手动，AUTO自动 |
| batch_id | bigint | 自动排课批次ID，可为空 |

说明：

- V1 手动排课数据 source_type = MANUAL
- V2 自动排课数据 source_type = AUTO
- 手动排课不需要 batch_id
- 自动排课生成的记录绑定 auto_schedule_batch

### 9.2 teaching_task 表无需大改

V2 暂时不建议大改 teaching_task 表。

任务排课进度可以通过 schedule 表统计得到。

## 10. 数据关系说明

### 10.1 教师禁排时间关系

```text
teacher 1 --- n teacher_unavailable_time
time_slot 1 --- n teacher_unavailable_time
```

### 10.2 自动排课批次关系

```text
auto_schedule_batch 1 --- n schedule
auto_schedule_batch 1 --- n unscheduled_task
```

### 10.3 冲突报告关系

冲突报告通过 object_type + object_id 关联不同业务对象。

这样设计比为每种冲突单独建表更简单。

## 11. 初始化数据建议

V2 初始化时需要写入默认排课规则：

```text
TEACHER_MAX_DAILY_SLOTS = 3
CLASS_MAX_DAILY_SLOTS = 4
PRIORITIZE_MORNING = true
AVOID_FRIDAY_AFTERNOON = true
ALLOW_SAME_COURSE_SAME_DAY = false
```

## 12. 注意事项

- 所有新增表都应有 create_time
- 重要业务表建议保留 update_time
- 业务删除优先使用逻辑删除
- 未排任务和冲突报告可以按批次清理
- 自动排课失败不能影响已有合法手动排课，除非用户明确选择清空旧排课
