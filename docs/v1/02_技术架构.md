# 02_技术架构

## 1. 总体架构

本项目采用前后端分离架构：

```text
Vue 前端
  ↓ HTTP / RESTful API
Spring Boot 后端
  ↓ MyBatis Plus
MySQL 数据库
```

前端负责页面展示、表单输入、课表可视化和接口调用。  
后端负责业务逻辑、登录认证、冲突检测、数据持久化。  
数据库负责保存用户、教师、班级、课程、教室、教学任务和排课结果。

## 4. 接口风格

统一使用 RESTful API。

示例：

```text
GET    /api/teachers
POST   /api/teachers
PUT    /api/teachers/{id}
DELETE /api/teachers/{id}

POST   /api/auth/login
POST   /api/auth/logout

POST   /api/schedules
GET    /api/timetables/class/{classId}
GET    /api/timetables/teacher/{teacherId}
GET    /api/timetables/classroom/{classroomId}
```

## 5. 统一返回格式

后端接口统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

错误示例：

```json
{
  "code": 400,
  "message": "排课失败：该教师在当前时间段已有课程",
  "data": null
}
```

## 6. 登录认证

第一版采用 JWT。

流程：

1. 用户输入账号密码
2. 后端校验用户
3. 校验成功后生成 token
4. 前端保存 token
5. 后续请求在 Header 中携带 token

Header 格式：

```text
Authorization: Bearer <token>
```

## 7. 核心业务逻辑位置

冲突检测必须写在后端 `schedule` 模块中，不允许只在前端判断。

推荐服务：

```text
ScheduleService
ScheduleConflictService
```

`ScheduleConflictService` 负责检测：

- 教师冲突
- 班级冲突
- 教室冲突
- 容量冲突
- 教室类型冲突
- 教学任务课时超限
- 状态不可用

## 8. 开发原则

- 第一版优先保证闭环完整，不追求算法复杂
- 后端必须做业务校验，前端校验只作为体验优化
- 代码结构清晰比功能堆叠更重要
- 所有模块先完成基础增删改查，再做排课逻辑
- 不提前开发自动排课、学生端、教师端
