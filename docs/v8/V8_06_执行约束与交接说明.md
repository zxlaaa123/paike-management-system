# V8 执行约束与交接说明（给执行方的硬规则）

日期：2026-06-12

本文档面向实际执行 V8 开发的 AI/开发者。以下规则是硬约束，与 `V8_01` 第 2 节锁定决策同级。

## 1. 阅读顺序

1. `V8_00_可行性研究.md` — 为什么做（含已拍板决策）
2. `V8_01_版本需求说明.md` — 做什么 / 不做什么
3. `V8_02_引擎设计.md` — 怎么做
4. `V8_03_API接口设计.md` — 接口与前端改动面
5. `V8_04_开发阶段计划.md` — 顺序与每阶段 DoD
6. `V8_05_测试与验收清单.md` — 怎么算做完
7. 项目根 `CLAUDE.md` — 环境与工具规范（PowerShell 优先、后端启动方式、测试数据隔离等），**全部继续有效**

## 2. 禁止事项（红线）

1. **不修改**以下现有代码的行为：`AutoScheduleService`、`ScheduleConflictService`、四个旧策略的生成逻辑、`ScoringFunctions` 既有方法的公式。允许的改动上限：为接入所需的**新增**分支/字段/方法。
2. **不新增数据库表和列**。需要持久化扩展信息时写入现有 log/extra 字段。
3. **不引入新第三方依赖**（包括 OR-Tools、commons-math 等；JDK 标准库自给自足）。
4. **不做单双周/周次**。
5. `engine/` 包内不得出现 Spring 注解、Mapper、`Math.random()`、无种子 `Random`、`System.currentTimeMillis()` 参与算法决策。
6. 不跳阶段：阶段 1 对拍测试（`V8_05` T2）不绿，禁止动阶段 2。
7. 不删除、不弱化任何既有测试。

## 3. 决策升级流程

执行中如果发现文档与代码现实冲突（例如 `performance_baseline` 没有 extra 字段、`ScheduleGenerateRequest` 结构与预期不符），处理顺序：

1. 文档明确给了降级方案的（如 `V8_03` 第 4 节），按降级方案执行并在阶段记录中注明。
2. 没给降级方案、但不触碰红线的：选择改动面最小的方案，在阶段记录中注明。
3. 触碰红线或锁定决策的：**停止开发**，写明冲突点，等用户裁决。

## 4. 分支与提交纪律（沿用项目既有惯例）

- 每阶段一个 feature 分支（如 `feature/v8-stage1-engine-model`），完成后 `--no-ff` 合入 `main`，**不 push**。
- 禁止 `git add -A` / `git add .`，逐文件 add。
- 提交信息格式沿用现状：`feat: ...` / `test: ...` / `fix: ...` / `docs: ...` / `merge: ...`，一阶段多次小提交优于一次大提交。
- 每阶段合入前：`mvn test` 全绿 + （有前端改动时）`npx vue-tsc -b` 通过。
