# V8 测试与验收清单

日期：2026-06-12

测试框架沿用现状：后端 JUnit（`backend/src/test/java/...`），E2E Playwright（`tests/`）。新增引擎测试放 `backend/src/test/java/com/paike/scheduler/engine/`。

## T1 冲突检测器单元测试（阶段 1）

每条硬约束至少一正一反用例，纯内存构造，不依赖 Spring/DB：

- [ ] 教师同时段冲突（TEACHER_CONFLICT）
- [ ] 班级同时段冲突（CLASS_CONFLICT）
- [ ] 教室同时段冲突（ROOM_CONFLICT）
- [ ] 容量不足（CLASSROOM_CAPACITY_NOT_ENOUGH，含人数/容量未配置两个分支）
- [ ] 实验课非实验室 / 机房课非机房（ROOM_TYPE_MISMATCH）
- [ ] 教师禁排（TEACHER_UNAVAILABLE）
- [ ] 教师/班级每日上限（边界：恰好达到上限再插一节必须拒绝）
- [ ] 同课同日（ALLOW_SAME_COURSE_SAME_DAY=false 拒绝 / =true 放行）
- [ ] 每周课时上限（TASK_NOT_FULLY_SCHEDULED）
- [ ] place/remove 对称性：place 后 remove，所有计数器/位图恢复原状（随机操作序列 property 测试）
- [ ] 锁定项预占用后，冲突位置不可用

## T2 双跑对拍测试（阶段 1，本版本质量基石）

- [ ] Spring 测试装载真实 schema 的随机数据集（≥3 套规模：10/50/200 任务）
- [ ] 枚举全部 (task, slot, room) 组合，分别调内存 `check` 与 DB 版 `checkConflict`
- [ ] 断言：允许/拒绝结论一致，且拒绝时 TYPE 标签一致
- [ ] 增量对拍：随机 place 若干 assignment 落库后重跑一轮，仍逐格一致

允许的已知差异必须在测试内注释并在 `V8_FINAL` 记录（原则上不应有）。

## T3 回溯求解器测试（阶段 2）

- [ ] **贪心必败但有解**的构造用例：如 2 个任务、2 个时段、1 间教室，贪心按排序把任务 A 放进唯一能容纳任务 B 的位置 → 贪心 1 个未排，回溯 0 个未排
- [ ] 真无解用例：回溯穷尽后正确报 PARTIAL/FAILED，未排原因 TYPE 正确
- [ ] 回溯预算触发：构造大搜索空间，maxBacktracks=10 时正常降级收尾、不超时不挂死
- [ ] MRV 排序：剩余候选少的任务先被选中（构造可断言的确定性场景）
- [ ] 锁定项不被移动

## T4 SOLVER_V8 集成测试（阶段 2）

- [ ] 经 `/api/v3/schedule-generate` 用 SOLVER_V8 生成，`schedule_plan` / `schedule_plan_item` 落库正确，`validatePeriodPair` 不变式满足（startPeriod 奇数等）
- [ ] 未排任务落 `schedule_unassigned_task`，generate log 有记录
- [ ] 性能基线有记录（成功与失败两个分支）
- [ ] 旧四策略行为回归：相同请求结果与改动前一致（至少跑通现有 `SchedulePlanServiceTest` 等全部既有测试）

## T5 退火优化器测试（阶段 3）

- [ ] 可复现：同 seed 同数据两次 solve，输出 assignment 集合完全一致
- [ ] 单调性：退火输出的目标函数值 ≤ 输入可行解的目标函数值
- [ ] 硬约束保持：退火输出每个 assignment 过 `check`，全程无硬违规
- [ ] **目标函数对拍**：同一解，`ObjectiveFunction` 算出的各 penalty 与落库后 rescore 写入 `schedule_score_detail` 的 penalty 一致（scale=4 精度内）
- [ ] 邻域算子：移动/交换后解仍可行；锁定项不参与邻域
