# V8 开发阶段计划

日期：2026-06-12

总原则：四个阶段，每阶段独立可验收、可单独合入 `main`，任一阶段后停止，项目仍处于可交付状态。分支与合并纪律见 `V8_06`。

## 阶段 1：内存模型 + 冲突检测器 + 双跑对拍

**产出**

- `engine/model/`：`EngineContext`、`EngineTask`、`Assignment`、`EngineSolution`
- `engine/conflict/InMemoryConflictDetector`
- service 层装载器（从 Mapper 装载 → 构建 `EngineContext`，含锁定项预占用）
- 单测：检测器每条规则的正/反用例；**对拍测试**（核心，见 `V8_05` T2）

**验收**

- 对拍测试通过：同一数据集上，内存检测与 `ScheduleConflictService.checkConflict` 对全部 (task, slot, room) 组合逐格结论一致（含失败 TYPE 一致）
- 不接入任何现有流程，现有测试全绿（本阶段对线上行为零影响）

## 阶段 2：回溯求解器 + SOLVER_V8 接入

**产出**

- `engine/solver/BacktrackingSolver` + `SolverConfig`
- `V3ScheduleGenerateService` 接入 `SOLVER_V8` 分支（落库、未排、日志、rescore、性能基线）
- `ScheduleGenerateRequest` 加 `solverSeed` / `solverTimeBudgetMs`
- 前端：策略下拉 + `strategyText` 映射
- 单测：构造"贪心必败但有解"的数据集（见 `V8_05` T3），验证回溯排满

**验收**

- 标杆数据集上：`SOLVER_V8` 未排任务数 ≤ 现有四策略最少值；"有解"用例 100% 排满
- 回溯预算/时间预算触发时正常降级为 PARTIAL，不挂死
- 现有 52 E2E + 后端单测全绿

## 阶段 3：模拟退火优化器

**产出**

- `engine/optimize/`：`AnnealingOptimizer`、`NeighborOperator`、`ObjectiveFunction`
- 接入 SOLVER_V8 流程（回溯解 → 退火 → 落库）
- 单测：同种子可复现；目标函数与 rescore 同源对拍（见 `V8_05` T5）；退火后分数单调不降

**验收**

- 标杆数据集上：`SOLVER_V8` rescore 总分 ≥ 现有四策略最高分
- 同 seed 同数据两次生成，plan items 完全一致
- 现有测试全绿

## 阶段 4：性能对比报告 + 收口

**产出**

- 性能/质量对比脚本或测试（300 任务级合成数据集：新旧引擎的耗时、得分、未排数）
- `docs/v8/V8_FINAL_验收记录.md`（格式对齐 `V7_FINAL_最终验收记录.md`：阶段提交清单、验证命令、结果、清理记录）
- README 中策略说明补一行

**验收**

- 300 任务规模下 SOLVER_V8 总耗时 < 时间预算上限（默认配置 ≤ 15s）
- 完整 `npm test`（E2E）实机通过
- 对比报告数据落档

## 时序与依赖

```
阶段1 ──► 阶段2 ──► 阶段3 ──► 阶段4
（严格串行，不允许跳阶段；阶段1 的对拍不绿，禁止开始阶段2）
```

## 各阶段共同的完成定义（DoD）

1. `mvn test` 后端全绿（含本阶段新增测试）。
2. `npx vue-tsc -b` 通过（涉及前端改动的阶段）。
3. 不改动 `V8_01` 第 2 节锁定决策；如确需变更，停止开发，先更新文档并经用户确认。
4. 提交信息与分支规范见 `V8_06`。
